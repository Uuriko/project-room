# Instruction pack — Public room pages (what a non-member sees of a room)

## 1. The piece

The public, no-login view of a room itself: the opt-in room page, its JSON twin, its proof child page, the separate read-only conversation face, and the directory listing a stranger discovers them through — plus the opt-in boundary that decides what crosses from a private room to any of them.

**Scope fence (read first):** receipt *detail* reads, the public receipts wall, and settled-lot (`lot_`) reads are **not** this piece — they are covered by the settled-lot / public-proof packs and bound PR **#4998** (lot reads consult the authoritative recorded receipts setting; money-adjacent, lands singly, bound at `2f2ca14da78b38979a97f77dcc1e340adc73ccdb`). This pack covers the room page that *links to* receipts and the toggles that gate that link. It never re-designs a receipt face.

## 3. What fantastic means

A non-member can find a public room, understand in one screen what they are looking at and what they are *not* looking at, and act on it — and an owner can publish, share, and unpublish a room knowing exactly what crosses the boundary, with every surface agreeing about whether the room is public.

Concretely, on the specimen matrix of §5 (private / page-on / page+receipts-on / directory-only / face-only / archived / operator-unpublished):

- **Boundary stated on the page, in ≤45 words, in the first screenful:** every `/r/` page (HTML and JSON twin, same words) carries a boundary line of the proof page's honesty standard, e.g. in substance: *this page is public because the room's owner turned it on · it shows only the title, purpose, counts, names members chose to show, tasks chosen for this page, and published receipts · messages and files are never on this page · turning the page off removes it.* Plus the recorded opt-in date (`setAt`, already loaded) rendered as "Public since <date>". A stranger can answer EXP-8's two questions — *who chose this?* and *what happens if they turn it off?* — from the page alone.
- **Findability is one connected graph, with 0 dead ends in the matrix:** a directory entry for a room with a public page links to it (one click C → A); a room page for a directory-listed room says so and links back; the B-namespace 404 for a slug-shaped id names the distinction ("public faces use a `pub1.` code; room pages live at `/r/<room-id>`") instead of denying a face exists; and no first-party surface (directory, sitemap, llms packets, room page) links to a page that 404s.
- **Retirement is total and immediate:** page off, archive, or operator unpublish each remove, by the *next* anonymous request, the HTML, the `.json`, the proof child (when receipts-driven), and the sitemap loc — with **0** occurrences of a join token anywhere in the retired responses (the §2.1 specimen is the regression case: after #5070 lands and the deploy carrying it ships, it must 404 styled for browsers, its token must appear in no response, and the sitemap must contain no `/r/` loc for it). No shared-cache residue: the existing `no-store` posture on A/A′ (http.mjs handler comments) is preserved and asserted.
- **The owner gets the address at the moment of choice:** enabling the toggle reveals, in the same control group, the canonical `/r/<room-id>` URL as a labelled link with a copy button (pattern: the setup-prompt copy helper already on the page) and a "view as a stranger" open — ≤1 click from toggle to a copyable address. B gains the same class of control (§4 step 4): status, address, enable/disable/rotate, and consequence text naming what B actually publishes (handles + non-DM messages), so the two switches' different scopes are visible *before* either is flipped.
- **Indistinguishability holds:** unknown, never-published, page-off, archived, and operator-unpublished slugs return the **same** styled 404 to browsers and the same `not_found` envelope to JSON clients — HTTP status, body shape, and `X-Robots-Tag: noindex` identical across the five cases (the current A behaviour at http.mjs:2426, extended to archived by #5070). No case leaks title, counts, existence, or a join token.
- **Whitelist, proven by test:** A's HTML+JSON contain 0 message bodies, 0 file names/contents, 0 member ids, 0 emails, 0 permission lists, 0 DM hints; a name appears **iff** that member's `publicName` is on, a task **iff** its `publicTask` is on, a receipt title **iff** the visibility predicate in `public-visibility.mjs` passes it. B contains 0 DMs (not counted, not hinted), 0 member ids/emails/secrets/invite codes, bodies truncated at 2,000 chars with the truncation marked.
- **Presentation parity with its own child:** A renders from the design tokens in both themes (dark default + light), at the product's 2px focus standard and ≥44px coarse-pointer targets (the #5055 public-template standard — §4 step 0), with a per-room share description taken from the room's own purpose (already the meta description) and no regression to A′.
- **Performance:** `/r/` HTML p75 ≤ 2 s over a 20-sample anonymous production probe post-deploy (today's single sample: 3.87 s); the page's receipt scan stays bounded (existing `ROOM_RECEIPT_SCAN = 200` cap and 5-receipt fill in `visibleRoomReceipts()` are not raised).
- **Showcase hygiene:** the sitemap's `/r/` set is exactly the set of live, non-archived, opted-in rooms — 0 test/QA specimens presented as the product's public rooms *by the system's own state* (retirement correctness produces this; no hand-curation, no denylist in this pack).

Exemplars worth matching: the product's own **proof page** (`PROOF_HONESTY` — honesty lines derived from what the page actually shows, printed on the page), its own **demo room** (first-line labelling of what the content is and is not), and GOV.UK-style "what this page does not show" boundary copy — short, factual, adjacent to the content it describes.
