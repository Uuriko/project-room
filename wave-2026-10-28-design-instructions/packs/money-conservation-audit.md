## 3. What fantastic means

An operator (or Jill) can answer "is the money ledger intact right now, in every room?" from a surface, without opening a database file — and a forged, replayed, or double-appended payout is caught by the system itself within one audit cadence.

Concrete end state and numbers:

- **Coverage:** 100% of rooms with escrow activity audited at least once per hour (the #4135 `escrow-conservation` cadence); rooms with no escrow activity cost 0 ms (job disabled, with a named `disabledReason`, like `escrow-epochs`).
- **Detection:** T1, T2, and T3b repros from #4125 all flagged **through the job path**, not only by calling the function — T3b's forged pair fails with a violation naming the bounty, the kind (`payout`), expected millis, and actual millis. Zero false positives across the ~25 existing suites that assert `verifyConservation().ok`, and across all six honest settlement shapes #4135 pins (full pay, split, release+compensate, dispute-cancel, reject, claim-timeout refund, verdict-legs-at-approved).
- **Visibility:** a violating tick is **red, not soft-passed**, on `GET /api/health/jobs` within one cadence of the forgery landing, with `errors` = number of violating rooms and `failureDetail.code = "conservation_violation"`; the operator log line names the room and the first violation (the #4135 shape). No bounty ids, amounts, or account ids appear on any public health surface — counts and stable codes only (the integrity-job precedent at `server/jobs.mjs` `integrity`).
- **Drill-down:** from a red tick, an operator reaches the exact offending `(room, bounty, kind, expected, actual)` in **≤2 steps**: (1) health surface / log line names the room; (2) the operator script run against that room's database (or its backup copy) prints a structured per-bounty violation record, not only prose strings. Script exit codes stay `0/1/2` exactly.
- **Cost, measured not assumed:** the full pass timing on the largest production room's journal is on file (ms per room and ms per 1,000 journal rows), and the recorded cadence keeps one full pass inside the slow-job deadline with the cooperative between-rooms yield intact. If the measured pass exceeds the deadline, cadence or per-tick room batching is adjusted **before** landing, with the measurement in the PR body.
- **Legacy disposition:** every pre-settlement-records terminal bounty that trips reconciliation has a named disposition record (honest-legacy vs real violation) reachable from the runbook; the steady-state target is **0 undispositioned legacy violations** — a red tick after disposition week means new corruption, full stop.

Exemplar to match: the `integrity` job in the same file — sanitized public detail (stable codes/classes only), raw identifiers confined to the operator log line, tick stays failing until the underlying state is repaired.
