# Instruction Pack — Room Search (in-room message search)

## 1. The piece

In-room search: a member in the web room types in the topbar search box and finds messages (and work) from the whole room, including archived history, then jumps to the hit. Three layers, verified against source extracted via `git archive` of main `aaa749065a6451321a949ddcb923f3174504fe35` into this lane's scratch (the shared clone was not read):

- **Web UI (the gap this pack commissions).** `index.html` lines 204, 228–234 (`#topbar-search-toggle`, `#search-form`, `#message-search`, Mentions/Pinned toggle buttons, `#search-results`/`#search-list`/`#search-count`); `src/app.js` `renderSearch()` (~line 2809–2845) and its listeners (~4927–4944); `src/conversation.js` `searchMessages(state, query, limit, …)` and `parseSearchQuery()` (lines 404–439). Today `renderSearch` searches **only the locally held projection state** — it never calls the server search endpoint.
- **Server endpoint (exists at main; upgraded by bound-for-landing PR #5112).** `Store.search(token, roomId, query, kind, …)` in `server/store.mjs` (~line 5356), route `GET /api/rooms/{roomId}/search?q={needle}` (route-table id `search`, `server/routes/table.mjs` line 110), agent-client wrapper `RoomAgent.search()` in `client/room-agent.mjs` (~line 1101). Kinds: `all | messages | work | pinned`; `limit` 1–200; opaque `before` cursor (`nextCursor`, kind/query-bound, cursor code at `store.mjs` ~6920–6955); errors `invalid_search` / `invalid_search_cursor` (422). All privacy filters run server-side before cursor resolution: PRIV-2 history floor, tombstones, pins, muted authors, targeted-DM visibility — neither hits nor `total` may leak a filtered message.
- **Why "ranked search was already wired" was only half true (consultation correction C-3, as confirmed by discovery-50).** Ranked term-frequency search existed for the **Inbox** — `server/inbox-search.mjs` (`indexMessages`/`search`, "results rank by total term frequency"; header notes store integration was a later slice, since wired as `store.inbox.search`). Room messages had no ranking and no index: at main, `Store.search` is a case-insensitive **exact-phrase substring scan** (`m.body.toLowerCase().includes(needle)`) over the projection plus `archivedMatchingRecords`. Discovery-50 lanes B4 and G1 confirmed C-3's FTS5 direction with executed numbers (see §2); PERF-ADOPT lane L09 then built it as PR #5112 (§4, Step 0 — do not re-build it).

This pack targets **main after #5112 lands** (production `ca37fee4` has neither #5112 nor this client work; do not acceptance-test the folding/AND behaviour against production). ## 3. What fantastic means

A member can find **any message they are allowed to read, ever posted in the room**, from the one search box, and land on it:

- **Completeness:** a query for a term that occurs only in an archived (pre-window) message returns that message; the displayed total equals the server `total` for that caller — never a window count. Zero false completeness: if the server leg is unreachable, the UI says results are from loaded messages only, in those words.
- **Quality (the #5112 numbers, held at the UI):** multi-term queries AND their terms (recall 1.000 on the #5112 bench corpus, vs 0.667 phrase-scan); diacritics fold both ways (`zurich` finds `Zürich`, `cafe` finds `CAFÉ`); non-ASCII precision@10 = 1.00 on the pinned fixtures. Whole-token matching is the accepted trade: `deploy` no longer hits `deployment` — the empty-state copy stops promising phrase/name matching the engine no longer does (see §4 Step 3).
- **Reach:** more than 50 hits are all reachable — paging follows `nextCursor` until it is null; a cursor-walk over a fixture room partitions the full hit set exactly (no duplicates, no gaps), the same property #5138's critic proved server-side (23-hit union exact).
- **Speed/feel:** keystrokes feel instant — local window results paint immediately, server results replace/extend them without moving focus or losing the typed query; a superseded request can never overwrite a newer one. Server leg stays in #5112's measured band (store-level p50 ≤ 0.24 ms on the 5,000-message bench; no new per-keystroke full scans on the client for rooms above the held window).
- **Safety:** a hit a caller may not read (pre-join floor, muted author, someone else's targeted DM, tombstone) never appears and never moves the count — identical result sets for the local and server legs on the same loaded window.
- **Exemplars to match:** Slack search (one box, total count honest, jump-to-message in context) and Discord's search panel (paged results, "x results" that means the whole server history, not the loaded slice). Match the honesty and the jump; do not copy their filter DSL — the only query syntax here stays `mentions:me` / `to:me` / `@me` (`parseSearchQuery`) plus the Mentions/Pinned toggles.
