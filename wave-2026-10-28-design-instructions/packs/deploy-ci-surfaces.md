## 3. What fantastic means

A new contributor, human or agent, opening their first PR can answer every CI question from the PR page and `CONTRIBUTING.md` alone, in under 2 minutes, without asking anyone:

1. **Unlabelled state explains itself in the run.** Within the same workflow run that skips (target: explainer job completes in <60 s, 0 install steps, 0 test suites), the PR's `test` run carries a visible note naming: heavy CI is waiting for the `ready-to-land` label; a maintainer adds it; `skipped` here means "not started by design", not "failed"; `safety-net`, `pin-gate`, and `review-mechanical` running is the complete expected unlabelled state.
2. **Docs match the machine.** `CONTRIBUTING.md` describes the gate, the draft rule, who labels, the designed skips that persist after labelling (`coverage` on PRs, `quarantined-tests`, `full`), and the sole required check `room/release-lease` — and every sentence is true against the workflow YAML at the head it ships in (acceptance re-greps both).
3. **No silent runner waste either way.** Unlabelled PRs still run zero heavy jobs (runner-minutes for the gated suites stay ~0 beyond the light workflows, as today); labelled PRs get exactly one full generation per settle — the explainer never triggers, duplicates, or delays it.
4. **The registry tells the truth on main.** `tests/quarantine.json` at main lists the real flakes (7/7 from #5015), `node scripts/quarantine-check.mjs` exits 0 **before** `repair_by`, every entry is narrowed to runnable `file > test name` form so `npm run test:quarantined` actually executes entries (>0 tests run, non-blocking), and the 2 MUT-04 orphans have an owner and a date or a recorded deletion decision — zero known flakes invisible to gates.
5. **Coverage is a signal again.** Three consecutive main-side coverage executions (scheduled or dispatch) end `coverage` job = SUCCESS with the log showing the thresholds step actually evaluated (not skipped, not died in a spawned child), and the aggregator `test` job SUCCESS on those runs. A red coverage job after this work means a threshold or a real test failure, never a harness spawn error.
6. **One red = one cause, visibly.** On any red PR generation, the primary failing job is identifiable from the check list without opening the aggregator logs (the aggregator echo is labelled as an echo in its step summary — stretch wording in §4 Step 4; if it cannot be done without restructuring jobs, it is dropped, not faked).
