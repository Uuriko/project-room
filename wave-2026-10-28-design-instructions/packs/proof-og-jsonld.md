# Instruction pack — OG / JSON-LD: social & structured metadata for receipts and public pages

## 1. The piece

The share layer: everything a stranger, a crawler, a chat unfurler, or a search engine receives about a public receipt or public page **before clicking** — Open Graph / Twitter meta, the per-receipt OG card image, the embeddable badge, the pre-filled share text, and the schema.org JSON-LD block — plus the same metadata on the two public collection surfaces (the receipts index and a room's proof page).

Vocabulary truth to honour throughout: public-work receipts carry a recorded verification fact, `verification: "hash_only" | "system_checked"` (composed onto the receipt; visible on every `.json` face), and a delivery `state` (submitted / verified / rejected, #3733 outcome composition). Receipts are **unsigned** — the signer is unprovisionable today (Invariant 17 does not hold in production; no seed slot in code) — so no surface may imply signing.

## 3. What fantastic means

One vocabulary, one grader, every surface: a stranger who sees only a chat unfurl, a search snippet, or the JSON-LD block learns exactly what the receipt page itself says — who ran the checks, what level of proof the record carries, and (for public-work) what state the delivery is in — and never a stronger or weaker claim.

Concrete end state, measurable:

- **0 false / 0 self-contradictory** share blocks on re-probe: all 7 E3-probed receipts (6 `pwr_` + 1 `wir_`, ids in `~/workspace/wave-2026-10-27-user-testing-2/lanes/08-02-public-receipt-detail/evidence/selected-ids.txt`) grade truthful against their own `.json` faces on production after deploy — og:description, twitter:description, meta description, JSON-LD Proof level **and** JSON-LD description, badge alt, share text, OG card subtitle all agree with each other and with the `.json`.
- **Single assignment point:** `grep -rn "proofLevelOf" server/` shows the share layer and the proof page both consuming the one graded function; no `shareProofLevelOf`-style local override remains; the false-premise comment above `proofLevelOf` is gone.
- **Proof page parity:** for any room with a `system_checked` public-work receipt, `/r/<slug>/proof` (visible label + note), `/r/<slug>/proof.json` (entry `proofLevel`/`proofLabel` + counts — system_checked rows no longer counted as artifact-hash), and its JSON-LD `ItemList` all say "Platform-checked delivery", byte-identical label to the receipt's own share surfaces.
- **JSON-LD completeness for public-work:** the block carries Proof level + delivery state + verification as recorded (e.g. `additionalProperty` entries mirroring the `.json` values verbatim), still no ratings/review markup, still no names (the existing honesty rule in `receiptJsonLd`'s header comment stands).
- **No new claims:** no surface says "signed", "verified" as a bare headline, or "human" for an agent reviewer; word count of each verdict line stays share-sized (one breath — label + scope in a single line, the existing `LEVEL_SCOPE` discipline).
- Exemplar to match: the module's own stated principle — *"Structured data only mirrors the visible page"* (`receipt-share.mjs` l.107–109, distribution research R4) — applied without exception, the same standard the proof page's JSON-LD header comment already claims.
