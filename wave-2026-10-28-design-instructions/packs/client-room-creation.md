**Caps at main (verified in source):**

- Agent door: `AGENT_ROOM_CREATE_CAPACITY = 3`, `AGENT_ROOM_CREATE_REFILL_PER_SECOND = 3/86400` — per-identity token bucket, **3 rooms, one token back every 8 hours** (`server/agent-rooms.mjs:45–47`; the check sits past the idempotency short-circuit in `create`). Plus `AGENT_ROOM_LIMIT = 100` → 409 `pilot_limit` "Bounded pilot capacity reached; no room was created". Plus a growth-credit bypass: on a 429 the create can be funded by growth credits instead of failing.
- Account door: `ACCOUNT_ROOM_LIMIT = 100` memberships → same 409 `pilot_limit` (`server/room-lifecycle.mjs:26`, `:140`). Eligibility gate (`:138–167`): a provisional (room-key) account is refused 403 `room_creation_denied`; an account with **zero** active memberships may create (its first room); an account with memberships must be owner or hold `manage_members` in some active human membership, or spend a growth room credit, else 403 `room_creation_denied` "Creating a room requires membership administration in one of your rooms"; an account with any membership must have a verified email. The only upfront client disclosure of any of this is one hint sentence under the form (`index.html`): *"Your first room is free to create, but more rooms need membership administration in one of your rooms. Archived rooms stay readable and exportable."*
- Idempotency (both doors, do not break): client-chosen `roomId` is the key — same request returns the same room with `duplicate:true` (HTTP 200); a different room under that id is 409 `room_exists` / `request_conflict`. Agent door also accepts `requestId`; the budget is charged **after** the duplicate short-circuit, so retries never spend budget. The human client generates `room-<12 hex>` once per attempt and keeps it across a lost-response retry (`src/app.js:1321`).

## 3. What fantastic means

A stranger can go from sign-in to a working room without learning anything by refusal:

- **≤4 fields, one screen, ≤60 s.** The create form asks name, purpose, kind (defaulted), your name (prefilled from the account) — the template choice is optional and collapsed. Submitting lands the creator **inside** the new room (already true: `openAccountRoom(result.room.id)`), on a room that is not empty (point 3 below).
- **Every limit is stated before it bites, in numbers.** Before first submit, the form shows the account's actual standing: e.g. "This will be your 1st room. You can create rooms freely while you own or administer one; the pilot ceiling is 100 rooms per account." An agent caller gets the same truth machine-readably (delivered by #5134's `createBudget` on the agent door; §4 Step 1 adds the account-door analogue). Zero creation refusals whose body does not name the budget, its scope, and a true wait — measured by the §5 probes, not by copy review.
- **The first room teaches the product in one task.** Every first room — automatic, form-created, or template-created — contains exactly one seeded starter: the Room Guide pattern already in `server/starter-room.mjs` ("See how work closes here" + a small choice set), so the stranger's first screen contains a doable action whose completion demonstrates propose → claim → close → receipt. An agent-created room keeps its existing starter + `nextActions` (do not regress UT2's WORKING leg).
- **Renaming is ordinary.** An owner renames from room settings in ≤3 clicks (name field → save → every live face shows the new name on next read), with the 60 s cooldown and prior-title history from #5134, and proof already issued keeps the name it was issued under (the RRC cure's invariant, re-probed in §5).
- **Validation reads like the agent door's.** Every refusal names the field, the limit, and the actual value class ("Room name must be 1 to 120 characters") — the human client displays the server's message instead of replacing it with a generic sentence. No silent `maxlength` truncation: over-long paste is refused with the count visible.
- **Exemplars to match:** Linear's workspace creation (name only, everything else defaulted, user lands inside with seeded starter content) and Slack's workspace setup (first channel + first invite pre-staged, limits stated in plain counts). The standard is: defaults carry the user; the form only asks what cannot be defaulted.
