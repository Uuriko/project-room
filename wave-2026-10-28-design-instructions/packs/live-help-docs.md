## 3. What fantastic means

A stranger — human or agent — can go from a help link inside the product to a
working first call without reading source, and a maintainer can prove the docs
are fresh with one gate run instead of trusting a number in prose. Numbers:

- **Contract completeness, honestly labelled:** documented-but-not-served stays **0**; parity violations stay **0**; every `server/routes/table.mjs` row stays documented (**100%**, as today); the served-but-undocumented legacy count (478 strict / 436 canonical at housekeeping's base) **only ever shrinks**, is printed by the gate on every run, and every remaining legacy route is visibly marked legacy in the rendered document — zero routes a reader cannot classify as table or legacy.
- **Example coverage is measured, not hoped for:** every operation carries a quickstart example as a bare path, or an explicit `exempt:<reason>` in the fragment — coverage reported as `exampled / total` by the gate, target **554/554 classified** at this tree's count, with the exampled share rising and the exempt share shrink-only (same discipline as the `x-room-permission` and parity baselines). Baseline to beat, measured this lane: 21 `example` tokens / 554 operations.
- **Permissions and parity finish their baselines:** new mutating operations: **100%** with a well-formed `x-room-permission`; new route rows: **100%** with `parity: "mcp:<tool>"` or `exempt:<reason>`; the grandfathered baselines (115/141 rows without parity at housekeeping's base; mutating ops without the marker) are shrink-only and their sizes are printed by the gate.
- **Quickstart examples execute:** 100% of code blocks in the canonical quickstarts (`AGENT-START-HERE.md`, `CONNECT-AGENT-QUICKSTART.md`, `AGENT-QUICKSTART.md`, `HUMAN-ONBOARDING.md`, `USER-GUIDE.md`, `FAQ.md`) are classified `runnable` or `illustrative` in the source; every `runnable` block executes green against a local fixture server in CI (today: 2 runnable of 316 docs-wide, unlabelled, unre-run). A cold-agent walkthrough (`docs/COLD-AGENT-WALKTHROUGH.md` shape) completes docs+curl only, zero source reads.
- **In-product help reaches the docs in ≤ 2 clicks from any room screen** (desktop and 390 px mobile), lands on the section for the screen the user was on (room help → joining/work help; API help → the operation's fragment example), and every such link resolves — `docs-link-check` broken count **0**, orphan count **0**, and the in-product links themselves are inside a checked inventory, not hand-maintained HTML that can drift.
- **Freshness is one command:** `node scripts/openapi-gen.mjs --check` + `node scripts/docs-link-check.mjs` + `CI=1 npm run check` green at the exact head, with the gate output (counts, legacy residue, example coverage) quoted in the PR body — no prose total anywhere in `docs/` that a gate does not regenerate or pin (the 515/538/554 divergence cannot recur: `OPENAPI-CONTRACT.md` keeps its "trust the check" wording and loses any unpinned total presented as current).
- **Exemplars to match:** the repo's own best patterns — `docs/OPENAPI-CONTRACT.md`'s source-of-truth table and failure-line examples; Stripe-style one-worked-call-per-operation as the example bar (one real request + real response per operation, bare path, no host/prefix decoration); the llms.txt convention (short canonical path, depth behind links) for the quickstart hierarchy — one canonical quickstart per audience, everything else labelled a specialized door, exactly as `docs/INDEX.md` already declares for agents.
