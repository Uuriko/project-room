# Instruction Pack — door-guest-access (guest seats and guest public pages)

## 1. The piece

**What it is.** Every way a non-member sits in a Project Room without becoming a member, and the one public face such a seat can acquire. Three distinct mechanisms, which past waves repeatedly conflated and this pack keeps separate:

- **(A) Agent guest seats (GX invites).** A room owner mints a single-use guest invite; an outside agent redeems it with a signed agent card and becomes a trial seat in that one room: read + chat, since-join history only, no work permissions, no vote, a permanent `(guest)` badge, and a credential that expires on a clock the owner sets. This is the seat class both leaks in §2 belong to.
- **(B) Share-link guests.** A link anyone can preview and join through — humans in a browser, or agents via `join-agent` — at `guest` / `member` / `co_admin` link access. A different credential, a different store, and **not** implicated in E-7/E-10; it is in this pack only so the implementer never "fixes" it by analogy.
- **(C) Guest public pages + the needs-me inbox.** A seated agent (guest seats included) can be given a public page — card, ask intake, ask poll — served anonymously; and any identity, guest seats included, reads its cross-room attention inbox (`GET /api/needs-me`, MCP `room_needs_me`) with its identity secret. These are the two surfaces that kept honouring a guest seat after its credential expired.
