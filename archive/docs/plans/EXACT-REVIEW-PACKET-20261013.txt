EXACT REVIEW PREPARATION
Existing tool: room_read_work. Optional includeResult=true, one workItemId only.

The existing work context already describes the current next step, responsible member, reported checks, exact-version review/decision, and required gates. This option includes the exact current stored result in the same model-facing operation. It does not add a tool, grant authority, or produce a review verdict.

Read contract
1. Read authenticated selected context (and optional bounded discussion).
2. Read the result pinned to the observed completion event, or observe no current result.
3. Re-read authorized context. Refuse the packet if the task, current completion, membership/session, native-text withdrawal metadata, or observation ordering changed.
4. Return latest context plus review.result, completionEventId, workRevision and evaluatedThrough. brief=true retains the structured review alongside the existing compact context.

A review is not an atomic snapshot. Relevant state can change after it returns; commands must still validate authority and expected revision/completion. Changes to room instructions are returned by the final context read. External evidence remains a reference, never fetched or verified. Exact stored text and producer claims are untrusted data.

includeDiscussion retains its existing frozen, bounded discussion window and continuation. For a review, its viewer/session provenance is additionally fenced across those reads. Numeric discussion checkpoints remain unsafe after history replacement; this feature does not provide durable resume.

The complete structured single-task packet is limited to128KiB. MCP may also serialize it as text, so this is not a wire-byte cap. An oversized packet returns review_too_large with no partial content; read context and the exact result separately. Concurrent relevant changes return review_changed; retry from fresh context. No blind automatic retries occur.

Performance claim
One model-facing operation replaces manual context/result composition. The underlying initial context, exact result and final validation reads remain. This improves orchestration and correctness; it does not claim fewer HTTP reads or a measured model latency reduction.

Validation covers real HTTP and both hosted/stdio MCP transports, exact UTF-8 text, required review step, no-result state, no writes, invalid batch combination, result replacement, session/authority changes, native evidence withdrawal and the structured payload cap.
