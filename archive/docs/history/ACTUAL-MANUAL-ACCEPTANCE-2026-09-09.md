## Boundaries

Browser/direct-client reads use the owner's private fixture credential; the exported packet does not. ## Design findings and next work

The return-code correlation works across a fresh browser session. The owner can inspect the exact text without copying an agent credential or setting up a live agent. The existing provenance warning correctly explains what is missing rather than presenting the result as approved.

Two frictions remain worth a complete, bounded refinement:

- The copy packet asks for both the artifact and check notes. They return as one message and become one exact-text result. In this exercise, the welcome and its two status notes are preserved together. A future explicit artifact/notes structure should retain the original answer, separate actual checks from claims, preserve exact version references, and work equally through browser, direct client and MCP. Do not silently strip notes, infer structured check success from text, or call this whole body a finished welcome.
- Manual contributors can credit only existing member identities or Unknown. Copying should not force a live integration, and unknown authorship must not be relabeled as verified simply to unblock review. Evaluate an explicit reported external-producer model and evidence for reviewer independence before changing that gate. Genuine uncertainty must remain representable.

The next implementation should address those content/attribution boundaries without adding another dashboard or burying them in more onboarding copy. Separate mailbox source rebasing and recovery limits remain pending; native-host review requires current usage approval.
