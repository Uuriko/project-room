# A dependable conversation-to-result journey

September 28, 2026. Refined after the Linear comparison, two independent agent critiques, a fresh native-agent exercise and direct browser exploration with synthetic local data.

## Product promise

Ask once, let an accountable agent work, intervene when a decision matters, and receive a useful result. Work should retain its identity across sessions, specialists, reviews and repeat runs. Human simplicity and agent capability must use the same underlying facts.

## Evidence and limits

- Native production tools: inbox suggested ordinary replies despite an empty incoming open-request list. Historical messages are useful context, but are not proof of an obligation.
- Native selected-work read: a completed task still carried raw session status `queued`. The human session card already had a presentation helper; agents needed the same explicit presentation without rewriting recorded status.
- Real local RoomStore regression: capped cross-room attention discovery could advance beyond eligible omitted items. The new regression spans more than forty rooms, kind caps and equal land timestamps.
- Human browser exploration: existing linked work cards already identify the next actor and expose details. Unique human names were clipped by long IDs in the participant rail. Event-counter jargon was screen-reader-only, not visually displayed; moving it into connection details addresses accessibility clutter without misrepresenting a visual bug.
- Existing tests already exercise transport/database restart, handoff, correction, exact-version review and owner decision. Reuse them. These tests do not prove actual independent hosts wake and execute automatically.
- Production Google sign-in remained on its provider loading screen during this attempt. No root cause established. Authenticated human exploration therefore used a disposable local fixture; no claim of testing John's signed-in production workspace.
- A fresh request for Instinct's firsthand feedback was posted in the existing room. Pending feedback is not evidence of agreement.

## Current release: trustworthy attention and readable continuity

1. Enumerate attention without skipping eligible undiscovered items. Bound each page, carry continuation, preserve numeric/map cursors, handle timestamp ties and expose `hasMore`. A discovery cursor is not completion or acknowledgment.
2. Separate optional conversation from formal open requests. Keep historical messages and current status reads; no text-based auto-resolution. Put known open requests first and describe delivery timeout separately from overdue work.
3. Give agents the same display status as humans while preserving recorded session state. Displayed done cannot claim an external process ran or stopped.
4. Keep structural catch-up compact when ordinary chat/read markers change. Every response still returns fresh event cursors; work, policy, participant and claim changes invalidate the structural version.
5. Show readable unique participant names; retain IDs on demand and in consequential selectors. Duplicate names remain disambiguated. Put diagnostic counters behind connection details.

No new task database, workflow engine or inference dependency is introduced. Tests must fail for the intended baseline behavior and pass after the repair. Preserve permission and exact-revision gates.

## Subsequent milestones, using the same work record

### One useful job

Run both a coding task and a source-backed research task from request through accepted result. Reuse existing briefs, questions, artifacts and reviews. Measure repeated human explanations, coordination failures and time to usable output. Fix remaining observed gaps before adding interface categories.

### Recover across real hosts

Interrupt after a meaningful action and resume on another compatible session/host. Preserve completed writes, uncertain outcomes, artifact references and remaining scope. Reconcile uncertain consequential effects before retrying. Gate: no repeated user explanation or duplicate effect in the controlled demonstration. Database restart coverage alone does not satisfy this gate.

### Collaborate selectively

One responsible executor by default. Add a reviewer or specialist for a specific contribution; compare acceptance quality, cost and delay against single-agent work. Review exact revisions and route corrections back to the existing task. Do not require a personal-agent hierarchy.

### Adapt context

Build on the separate explicit contextual-tool-discovery work. Surface task-relevant actions first, then editable defaults, then evaluated bounded routing. Never infer new authority. Evaluate semantic selection against ordinary deterministic rules; keep a functional fallback. Do not ask users to select modes for routine work.

### Repeat successful work

Promote an accepted task into a draft routine with trigger, scope, executor, output, limits and stop behavior. Trial one bounded run; version configuration and preserve history. Gate: duplicate triggers cause no duplicate effects and edits have predictable run boundaries. Existing recipes must be inventoried before adding machinery.

### Share value and test paid demand

Invite someone to review or extend a specific result; let them reuse its successful procedure with their own resources and permissions. Test a fixed-scope recurring job people want to stop coordinating manually. Measure repeat demand and actual delivery cost before introducing marketplace/payment complexity. No money movement is part of this release.

## Delivery discipline

Bounded file claims; one integration owner; shared-checkout test freezes; independent review; exact candidate CI. Report reviewed, merged, deployed and live-verified separately. Never describe deferred milestones as shipped. Human cards, API projections and agent tools should read the same contracts rather than maintain parallel state.
