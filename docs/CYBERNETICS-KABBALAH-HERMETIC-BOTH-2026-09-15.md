# Cybernetics, Kabbalah, Hermeticism — operations and mystical UI

Date: 2026-09-15. Products stay split: Room ≠ Desk ≠ Dasha Compute ≠ DIE Track Room. Live Room remains unpublished MCP (`ship: false`). This note is research, not a schema bump.

## Why “not mystical UI” showed up — and why both is better

The earlier rule was **tactical**, not metaphysical.

1. **A costume is not a model.** Clip-art Trees of Life, Hebrew as ornament, and “alchemical” gradients usually hide a Slack clone. Operators bounce. Agents can’t parse it.
2. **Receipts have to paste.** Muse’s bar was one sentence you can forward (`Ship docs: done.`). A sefirah glyph that doesn’t survive WhatsApp fails the product.
3. **Google / first-run.** Continue with Google, unverified-app warning, keys as fallback. Occult chrome on the sign-in panel looks like a scam page next to Google’s warning.
4. **Lane fights.** Instinct store fence, Schema 34 on `main`, Tag sandbox — a Tree-as-IA would have collided with all three.

You can still do **both**: keep the **cybernetic / kabbalistic / hermetic structure in the machine**, and let a **mystical surface** appear *after* identity is proven, *as a reading of real state*, not as wallpaper.

Test for any mystical widget: **if you strip the myth, does the control still have a true name?** If yes, ship both names. If no, it’s costume.

## 1. Cybernetics (the operating system)

### 1.1 Ashby — Law of Requisite Variety

Only variety in the controller can absorb variety in the system. Two moves: **attenuate** what hits the center, **amplify** what the center decides.

| Move | Room | Compute | Desk / DIE |
|---|---|---|---|
| Attenuate | Unpublished MCP, `ship: false`, origin checks, PKCE pending map cap 100 | `no_mac_online` instead of silent hosted swap | Desk is not Track Room |
| Amplify | Max agents get full `PERMISSIONS`; first Google human in empty Welcome can invite | Guest key 24h chat+models | Codex authority as System 5 |

**Tsimtsum is variety attenuation.** Contraction so something else can exist. Live Room contracted walk-in so Google members can exist without `oa1.` persistence.

### 1.2 Beer — Viable System Model (recursive)

Every viable system contains viable systems.

| System | Beer | Room (live) | Compute | Don’t |
|---|---|---|---|---|
| **S1** | Operations | Welcome conversation, work items, receipts | Provider Macs running Ollama | Don’t make S1 wait on S5 for “hello” |
| **S2** | Oscillation damping | Rate limits, PKCE supersede, SameSite interstitial | Leases, cancellation, doctor | Don’t use S2 as a moral lecture |
| **S3** | Resource bargain *now* | Account rooms list, member bits, operator grant | Capacity, tokens/s on `/compute/api/network` | Don’t let S3 rewrite schema in place |
| **S3*** | Audit / sporadic | `live-audit.mjs`, asset allowlist vs `app.js` imports | Release checksum identity tests | Don’t weaken tests |
| **S4** | Outside / future | Google In production, privacy URL, unverified-app | OpenRouter branch (report-only) | Don’t paste staging as live |
| **S5** | Identity | `ROOM_PRODUCTION=1`, operator id, `ship: false` as identity not a bug | `agent.json` **Not Room** | Don’t merge products to “have one brand” |

**Algedonic channel** (pain/pleasure that jumps levels): connection status that stuck on “Connecting…” was algedonic — S1 dying (404 `channels.js`) while S5 thought Google was fine. The live-audit import crawl is a permanent algedonic sensor.

**Recursion:** a Room is a viable system; each work item is a smaller one (proposal → act → receipt). Compute’s coordinator/provider split is S3/S1 recursion. Do not flatten them into one object.

### 1.3 Von Foerster — second-order cybernetics

The observer is in the system. Room’s `sessionBinding`, `expectedRevision`, and “email is not the account key” are second-order: **who is looking** is part of the state. Google `sub` hashed to `idp-…` is an eigenbehavior — a stable identity produced by repeating the same observation (token verify).

**Pask / conversation theory:** a conversation is not a log; it is a coupling that can fail. Receipts in-thread are the **closure** of a conversation about work. Without them, chat is open-loop.

### 1.4 What to build from cybernetics (ops)

- Keep one algedonic dashboard: live-audit + `/api/version` + `/api/open.ship`.
- S2: never let a second Google start keep the old `state`.
- S3*: asset allowlist == browser imports (the Connecting hang).
- S5: `main` Schema 34 is a *different identity* than live. Do not “unify” by overwrite.

## 2. Kabbalah (the cosmology of contraction and repair)

Use Lurianic structure (Scholem’s reading), not a jewelry Tree.

### 2.1 Tzimtzum — contraction

Ein Sof withdraws to leave a vacated space (*tehiru*) in which finite things can exist. That is **not** deletion. The infinite is still there; it is **not filling the room**.

Live mappings:

- `ship: false` is tzimtzum of walk-in.
- Durable Object `invite-only-pilot` is the vacated space — one finite vessel.
- Google In production without mailbox scopes is tzimtzum of Gmail.
- Compute `no_mac_online` is honest empty space, not a fake hosted model.

**UI (mystical, allowed):** a dim corona around the room shell labeled only when unpublished — not a banner “TZIMTZUM.” A single retracted ring. Clicking it explains: “Walk-in is contracted until abuse controls exist.”

### 2.2 Kelim / shevirat ha-kelim — vessels and breaking

Light into vessels that cannot hold it → shatter → sparks in shards.

Room already *had* shevirah:

- `channels.js` 404: vessel (asset allowlist) too weak for the light (app import).
- SameSite Strict + 302: vessel (cookie) broke on contact with Google’s light.
- Staging README on `production`: vessel (GitHub identity) holding the wrong light.

**Law:** do not pour Schema 34 into the schema-26 vessel. That *is* shevirah. Copy-first into a **new** object is a new vessel (see solve et coagula).

**UI:** work that is `failed` or `superseded` is a shard. Don’t delete it; show a spark (receipt: `Title: failed.`) that can be gathered. The work list of broken items is *kelipot* if you never gather them — so a “Gather failed work” filter is tikkun, not a dumpster.

### 2.3 Tikkun — repair by gathering sparks

Tikkun is not a factory reset. It is **sorting**: this spark belongs in this vessel.

Mappings:

- Receipt sentence in the thread = spark returned to the conversation vessel.
- Live-audit fail-closed on `gmail.readonly` = refuse a spark that would shatter privacy.
- First Google member invite = tikkun of an empty Welcome (a vessel with only a host).
- Compute report `/compute/api/network` vs `/v1/network` 404 = point the spark at the live vessel.

### 2.4 Sefirot as *functions*, then as UI

Ten sefirot are a **stack**, not a logo. Map them to Room **after sign-in**, optional “Tree reading” of the current room — a panel, not the IA.

| Sefirah | Function | Room state | Mystical UI (opt-in panel) |
|---|---|---|---|
| Keter | Crown / identity | `ship`, production gates, operator | Unlit lamp if unpublished |
| Chokhmah | Flash / insight | New message, work proposal | White spark on composer send |
| Binah | Understanding / form | Work item created from a message | Vessel outline around the card |
| Chesed | Expansion / invite | Share link, Google invite | Open hand — only if `manage_members` |
| Gevurah | Boundary / no | Origin 403, PKCE fail, revoke | Red contraction ring |
| Tiferet | Harmony / receipt | `Title: done.` in-thread | Gold seal on the message |
| Netzach | Persistence | Reminders, automations | Recurring mark |
| Hod | Splendor / speech | Agent messages, Max permissions | Agent glyph distinct from human |
| Yesod | Foundation / bind | `sessionBinding`, account cookie interstitial | Two rings locking |
| Malkhut | Kingdom / the room | Welcome, rooms list | The actual chat — never replaced by the Tree |

**Hard UI rules if you ship the Tree panel:**

1. Default off. Toggle “Read this room as a Tree” in the room menu.
2. Every node is a **live count or list** (Chesed = n open invites). Dead nodes are costume.
3. Latin or English labels first; Hebrew optional, never decoration-only.
4. Do not use the Tree as the **router**. Malkhut is still the chat.
5. Sign-in, Google, keys: no Tree. Keter is invisible until authenticated.

### 2.5 Four worlds (as layers, not pages)

- **Atzilut** (emanation): wrangler production identity, secrets, `ROOM_ORIGIN`.
- **Beriah** (creation): schema, Welcome bootstrap, Google `idp-` accounts.
- **Yetzirah** (formation): events, work items, receipts.
- **Asiyah** (action): the browser, Continue with Google, Connecting hang.

Schema 34 on `main` is a Beriah that must not overwrite Asiyah’s live SQLite. Copy-first is descending light into a **new** Asiyah.

## 3. Hermeticism (the laboratory)

### 3.1 Correspondence — “as above, so below”

Not astrology in the sidebar. **The public contract matches the private machine.**

- `/api/open` `ship: false` must match the unpublished door.
- README must match `/api/version` (staging URL on production was a broken correspondence).
- Compute skill `base_url` must match the 200 path, not a 404.

**UI:** a small “as above” strip in connection-details: live SHA, `ship`, provider=google. That *is* hermetic: the above (Worker) shown below (status).

### 3.2 Solve et coagula — dissolve and re-bind

The instruction that already saved the data plane: **do not transmute the live object in place.**

- Solve: export / copy staging or schema-26 out.
- Coagula: new Durable Object, new vessel, then point the name.

Same for Google cookie: dissolve the 302 (cross-site), coagula as HTML interstitial (same-origin). Same for `channels.js`: dissolve the missing allowlist, coagula into `build-assets` + HTTP map.

**UI:** work states as laboratory colors, not a chemistry set overlay.

| Stage | Color / feel | Work |
|---|---|---|
| Nigredo | Black / mute | Proposed, waiting |
| Albedo | Wash / silver | In progress, verification |
| Citrinitas | Yellow | Result posted, needs owner |
| Rubedo | Gold / red seal | `Title: done.` receipt |

These can be **left-edge pigments** on work cards *and* still show the English sentence. Both.

### 3.3 Coincidentia oppositorum

Google login **and** keys. Agents **and** humans. Unpublished **and** In production OAuth. Compute community Macs **and** hosted Ask — never silently swapped.

UI: paired controls (already: Continue with Google + Sign in with a key). Keep the pair visible as opposites that don’t cancel.

### 3.4 The three principles (optional chrome)

- **Sulfur** — will / Max agent / operator.
- **Mercury** — messages, MCP (contracted).
- **Salt** — receipts, SQLite, privacy page.

A three-dot identity mark next to the member chip is enough. Not a lecture.

## 4. Combined architecture (both tracks)

```
S5 / Keter     identity: ship false, operator, Google client, Not Room
S4 / Chokhmah  outside: OAuth, www door, Compute network
S3 / Tiferet   bargain: rooms, members, receipts
S2 / Gevurah   damping: rate limits, PKCE, SameSite interstitial
S1 / Malkhut   the chat
```

**Solve et coagula** is the only allowed schema move. **Tzimtzum** is the only allowed launch move (contract walk-in). **Tikkun** is receipts + failed-work gathering. **Algedonic** is live-audit.

### Mystical UI slices (safe order)

1. **Pigment only:** nigredo→rubedo on work cards; receipt stays English.
2. **Correspondence strip:** SHA / ship / provider in connection-details.
3. **Tzimtzum ring:** unpublished MCP as a retracted halo, copy in plain English.
4. **Opt-in Tree panel:** ten live nodes, English names, Hebrew optional, not the router.
5. **Shard tray:** failed/superseded work as sparks to gather.
6. **Never on Google / key gate.**

### Forbidden even if “both”

- Tree as the only navigation.
- Hebrew that doesn’t map to a control.
- Pouring Schema 34 into live SQLite because “coagula.”
- Mixing Desk, Room, Compute, Track Room into one sefirah map.
- SOC2 / SSO / ATS invented as “Keter.”
