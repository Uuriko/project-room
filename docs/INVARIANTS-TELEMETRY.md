# Invariants telemetry contract

Who this is for: the invariant harness (producer, lane A1), the CI gate
(consumer, lane A12), and anyone rendering results for a PR comment.

## The results file

One JSON Lines file per run. UTF-8, one JSON object per line, appended as
the run progresses — readable mid-run.

- Default path: `results/invariants.jsonl` (relative to the repo root).
- Override: `INVARIANTS_RESULTS_FILE` env var (reporter library, CLI, and
  renderer all honor it). CI should point it at a per-SHA path, e.g.
  `results/invariants-${{ github.sha }}.jsonl`, so the workflow can upload it
  as an artifact:
  ```yaml
  - uses: actions/upload-artifact@v4
    with:
      name: invariants-results
      path: ${{ env.INVARIANTS_RESULTS_FILE }}
  ```
- `results/` is gitignored — results never land in git.

## Line types

### run_start

```json
{"type":"run_start","run_id":"inv_1728412800000_a1b2c3","repo_sha":"f48be87fc1a2...","harness":"node-invariants","harness_version":"0","started_at":"2026-10-08T23:31:04.123Z"}
```

- `run_id`: unique per run, generated by the reporter
  (`inv_<epochms>_<6 hex chars>`).
- `repo_sha`: full commit SHA of the tree under test.
  Resolution order: `INVARIANTS_SHA` env > `git rev-parse HEAD` in the
  working dir > `"unknown"`.
- `harness` / `harness_version`: free-form producer name; recorded so a
  renderer can say what ran.

### invariant_result

```json
{"type":"invariant_result","run_id":"inv_1728412800000_a1b2c3","repo_sha":"f48be87fc1a2...","name":"claim-release-compare-and-swap","status":"pass","duration_ms":14,"started_at":"2026-10-08T23:31:04.200Z","finished_at":"2026-10-08T23:31:04.214Z","message":""}
```

- `name`: stable invariant id (kebab-case, no spaces).
- `status`: one of `pass`, `fail`, `skip`, `error`.
- `duration_ms`: integer milliseconds, >= 0.
- `message`: one-line human detail; empty string when there is nothing to
  say. Keep it short — it lands in a markdown table.

### run_end

```json
{"type":"run_end","run_id":"inv_1728412800000_a1b2c3","repo_sha":"f48be87fc1a2...","finished_at":"2026-10-08T23:31:09.000Z","duration_ms":4877,"counts":{"pass":41,"fail":1,"skip":2,"error":0},"status":"fail"}
```

- `status` is `pass` when `fail + error == 0`, else `fail`.
- `duration_ms` is wall time from `run_start` to `run_end`.

## Producer API

`scripts/invariants-reporter.mjs` is the reference producer.

```js
import { InvariantsReporter } from "./scripts/invariants-reporter.mjs";

const rep = new InvariantsReporter({ outPath, sha, harness, harnessVersion });
rep.startRun();
rep.record({ name: "mint-throttle", status: "pass", durationMs: 12 });
await rep.check("claim-release-compare-and-swap", async () => {
  // throws -> recorded as fail with the error message; resolves -> pass
});
const summary = rep.endRun(); // writes run_end, returns { counts, status, runId, sha }
```

Shell harnesses can use the CLI instead; run state persists in
`<outPath>.run.json` between invocations:

```sh
node scripts/invariants-reporter.mjs start --harness my-harness
node scripts/invariants-reporter.mjs record --name mint-throttle --status pass --duration-ms 12
node scripts/invariants-reporter.mjs end
```

## Renderer

`scripts/invariants-report.mjs [results-file] [--fail-on-fail] [--out FILE]`
renders the latest run in the file as a markdown table for PR comments.

- Default file: `$INVARIANTS_RESULTS_FILE`, else the newest
  `results/invariants*.jsonl` by mtime.
- Exit 0 after rendering. Exit 2 when no results file exists.
  `--fail-on-fail` exits 1 when the latest run has any `fail`/`error`.
- With several runs in one file, only the latest run (by `started_at`) is
  rendered; the table header notes the run count.

Both the library and the renderer are covered by fail-first tests in
`tests/invariants-reporter.test.js` and `tests/invariants-report-render.test.js`.
