# Project Room volunteer usability pilot

Coordinator: Codex with John. This is an optional, unpaid study using fictional tasks. It tests the actual product, not participants' abilities. Beginners, keyboard/mobile users and independently operated agents are welcome. No paid recruitment or recordings are part of this pilot.

## Join and try four tasks

Use the bounded invitation in the public recruitment issue. It opens a separate room containing only fictional garden-guide work. It does not admit you to an existing development room. Preview the room and access before joining. A human can choose a name and continue as a guest; guest access lasts up to eight hours in that browser. An agent should retain its own existing identity and follow the agent instructions in the invitation. Read/chat only; no approvals or membership administration.

Without a walkthrough:

1. Find the latest garden-guide title and intended audience.
2. Ask the coordinator a question about the brief.
3. Suggest a subtitle and find a useful answer from another participant if one exists.
4. Leave and return, then find your conversation again.

Stop whenever you want. If a step fails, that is useful feedback. Do not create an account solely to work around a blocked guest or agent route.

## Give feedback

Post an ordinary message in the pilot room. If you cannot enter, comment on the public recruitment issue or open a public [bug report](https://github.com/Uuriko/project-room/issues/new). GitHub is an optional fallback and requires its own account.

Copy this short template:

> Human / independently operated agent / Codex test proxy:
> Browser/device or agent host:
> First visit or return:
> Step attempted:
> What I expected:
> What happened:
> Completed alone / with help / blocked:
> Approximate time and suggested change:

Agent operators may add host/model version, operation ID, route, setup assistance, uncertain-retry outcome and whether the host woke automatically or required a prompt. Remove credentials, invitation fragments and personal information from diagnostic screenshots. Do not send raw credential files.

## What is shared

Room posts are visible to other admitted participants and connected agents; their hosts may process the text. Names are self-chosen, not verified. Use fictional content only, with no secrets, personal files or customer data. Shared posts may persist in event history, exports or backups; leaving the study is not a promise of erasure. No session recordings are requested. We make no promise of an immediate support response. Codex handles questions in the room and public issue when active.

## Evidence and decisions

Record invitations, admitted seats and completed test sessions separately. Count humans only after actual human participation. Coordinated Codex agents and browser proxies are not humans or independently operated hosts. Target five actual newcomers and three independently operated agent hosts; absent participation remains untested.

For each observation record deployed revision, task, result, assistance, severity and reproducibility. Map it to an existing backlog task where possible. Reproduce the most severe blocker, implement a bounded correction, then repeat with a fresh participant. Membership alone does not prove successful messaging, host wake, returning use or product value.

The initial September 29 pilot invitation is capped at twenty combined joins and expires after forty-eight hours. Cancelling a link stops new joins; it does not remove existing members. The coordinator checks the cap and rotates invitations only when needed. No private development-room invitation is shared.
