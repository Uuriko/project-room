## 2. Security pass over `server/http.mjs`

Method: every route handler read end to end (`server/http.mjs:229-842`) with
the store methods it calls; checked auth on every write, origin and CSRF,
rate limits, body caps, error leakage, and what each response carries.

Handled correctly (no finding):

- Every non-`GET`/`HEAD` room route passes `protectWrite` (origin required,
  CSRF for cookie sessions, constant-time compare) and `rate('write:…', 60)`
  (`server/http.mjs:163-170`, `558`). Account-level writes (`/api/inbox/*`,
  `/api/account-session`, `/api/share-links/join`, `/api/invitations/accept`,
  guest-agent mint) each call `protectWrite` individually
  (`:312,324,350,355,398,433,461,482,510`).
- `Host` and `Origin` are checked on every request (`:237-238`); cookies are
  `HttpOnly; SameSite=Strict`, `__Host-` prefixed and `Secure` on HTTPS
  (`:167`); CSP, `nosniff`, `no-referrer`, `noindex` on every response
  (`:231-235`).
- JSON bodies are capped at 16 KB by both `Content-Length` and streamed bytes
  (`:181,186`); NDJSON import is capped at 8 MB (`:690`).
- 5xx responses carry a fixed message, never `error.message` (`:834`);
  unknown room ids answer 404 through `pathId` (`:27-32`).
- Secrets and hashes: plaintext credentials appear once, in the creating
  response only (`agent-identities.mjs:67`, `agent-invites.mjs:149`,
  `guest-agent-links` mint, `share-links` create). `GET share-links` and
  `GET guest-agent-links` return no token or hash. `diagnostics-export` is
  whitelisted scalars (`:735-747`). The one hash returned to clients is L6.
- Bounded tables: identities 5000, credentials 5000, account slots 10000,
  rooms 10000 events / 100 members / 500 work items / 4 MB projection
  (`server/store.mjs:747,774,1078-1084,1140,1740-1765`).

### Medium

**M1 — Webhook rate limit is keyed by source address, which Telegram shares
across every bot.** `server/http.mjs:293` applies
`rate('inbox-webhook:' + remoteAddress, 120)` before the secret is checked.
Telegram delivers all webhooks from a small egress range, so once #145 goes
live the 120/min allowance is a global cap across every connected bot; a 429
makes Telegram retry the same update and hold later ones. Fix (one PR): keep a
high per-address guard for unverified floods (for example 1200/min), and rate
the verified path per connection (`inbox-webhook-connection:<connectionId>`)
after `channelWebhooks.receive` matches the secret; pin both in
`tests/channel-connection.test.js`.

**M2 — The webhook shares the 16 KB JSON body cap.** `:297` reads the
update through `body(req)` (`:181,186`). A Telegram update embeds the whole
replied-to message (`reply_to_message`), so a reply to a 4096-character
message plus entities exceeds 16 KB; the 413 makes Telegram redeliver the
same update indefinitely and stalls the connection. Fix: give `body()` a
`limit` option, use 64 KB for the webhook route only, add the number to the
`channelSyncLimits` row of `docs/UNIFIED-INBOX.md`, and add a test with a
20 KB shape-valid update.

**M3 — On `main` the webhook accepts deliveries for a connection whose owner
must reconnect.** `server/channel-import.mjs:73-76` checks
`connection.state === "active"` from the stored JSON; it ignores the account's
current `auth_epoch`, so a connection that reads `reconnect_required` through
`connectionState()` still journals updates. **Fixed by #150** (`JOIN accounts`
and `connectionState(connection, row.auth_epoch)`). Fix: merge #150.

**M4 — Route documentation covers a third of the served surface.**
`docs/openapi.yaml` documents 23 path templates; `server/http.mjs` serves 65
(derived with #152's `routeCandidates`), leaving 42 undocumented, including
every `/api/inbox/sources/*`, `/api/account-*`, `/api/session`,
`agent-invites`, `reminders`, `charter`, `reply-*`, `share-links*`,
`diagnostics*` and `work-changes`/`work-discussion`.
`docs/ROUTE-AUTH-TABLE.md:15-31` omits `POST`/`DELETE
/api/rooms/:id/agent-invites` (`server/http.mjs:649-664`) although
`tests/route-auth-table.test.js:14` lists it, and it scopes itself to room
routes while the account-level writes above have no table at all. After #152
the count becomes 36 documented / 29 undocumented; #151 documents its two new
routes. Fix (docs PR): add the 29 remaining paths to `docs/openapi.yaml` with
their guard (`accountSession` or room credential), add the `agent-invites`
rows and an "account-level writes" table to `docs/ROUTE-AUTH-TABLE.md`, then
extend `scripts/open-routes.mjs --check` (#152) with a served-but-undocumented
assertion (`routeCandidates` minus openapi paths must be empty) so the gap
cannot reopen.

**M5 — Worker CPU budget is unmeasured.** `cloudflare/wrangler.jsonc:19` sets
`"limits": { "cpu_ms": 50 }`; `scripts/measure-cold-start.mjs` is absent and
no document records a measurement. A local proxy (import
`server/store.mjs` + `server/http.mjs`, fresh store `initialize`, server +
`/api/health`, three runs on Node 24.21.0) measured import 90-95 ms CPU,
fresh-store initialisation 22-30 ms, server + first request 35-36 ms, reopen
of an existing file 10-15 ms. Workers count module evaluation separately, but
the Durable Object's first request still opens the store and verifies the
36-table schema inside the 50 ms request budget, and #145 adds live network
calls on the send path. Fix: commit the measurement as
`scripts/measure-cold-start.mjs` (miniflare run of `cloudflare/room.mjs`
cold, reporting CPU per phase) and record the number in
`cloudflare/README.md`; decide #141's cap change against that number before
the Telegram live deploy.

**M6 — Two ready PRs stack on #145 and both edit the same files.** #151
(`server/http.mjs`, `scripts/runtime-package.mjs`, `docs/openapi.yaml`,
`docs/UNIFIED-INBOX.md`) and #152 (same four files plus `scripts/check.mjs`)
each contain #145's commits. Whichever merges second needs a rebase, and
#152's new gate will then run against #151's routes (they are guarded, so
the open-route set is unchanged, but `PROBES` in
`tests/invite-only-boundary.test.js` and both docs tables must still agree).
Fix: merge in the order #145, #150, #152, then rebase #151 onto `main` and
re-run `npm run check` before marking it ready.

### Low

**L1 — The thread route skips the shared room funnel.** `server/http.mjs:540-546`
handles `GET /api/rooms/:id/messages/:id/thread` before the `match` block:
no `pathId` decoding (`:548`), no `rate('read:…', 600)` (`:557`), and no
rejection of bearer account sessions or non-session cookies (`:555-556`);
`store.authenticate` runs with `allowAccountSession` defaulting to true
(`server/store.mjs:1149`). Fix: add `messages/{id}/thread` to the route
alternation or move the handler below `:557` and reuse `selected`/`auth`.

**L2 — `agent-invites` routes drop the session-binding fence.** `:652,658,662`
call `store.invites.list/create/revoke` without `fence`, and the methods take
no `expectedSessionBinding` (`server/agent-invites.mjs:108,226,242`), unlike
`identity-links` (`:632-641`, `agent-identities.mjs:77`). A stale account tab
acts as the currently signed-in account without the 409
`session_binding_changed` guard. Fix: thread the binding through the three
methods and pass `fence` from the router; one test per method.

**L3 — Two open routes read the body before rate-limiting.** `:525-526`
(`/api/agent-identities`) and `:533-534` (`/api/agent-invites/redeem`) await
`body(req)` and then call `rate()`. Bounded by the 16 KB cap, but the order
is reversed relative to every other rate-limited route. Fix: swap the two
lines in each handler.

**L4 — The NDJSON import reader lacks the guards `body()` has.** `:686-700`
has no `Content-Length` pre-check and no `aborted` handler (compare
`:181,191`), so a client that stops sending holds the promise until
`server.requestTimeout` (`:844`, 15 s). Fix: give `body()` a
`{ limit, contentType }` option and use it here.

**L5 — 5xx on non-room routes leave no operator trace.** `:836-840` records
and logs only when `diagnosticRoute()` resolves, which requires a room id
(`:85-94`); an `internal_error` on `/api/inbox/*`, `/api/account-session` or
`/api/session` is answered silently. Fix: `console.warn` every status >= 500
with `operationId` and the static route prefix regardless of room scope.

**L6 — `GET agent-invites` returns the stored code hash, and legacy codes
are bare SHA-256.** `server/agent-invites.mjs:88` returns `codeHash`;
`:57-59` hashes 8-symbol legacy codes with plain `sha256` (v2 codes use
scrypt). A `manage_members` holder listing invites can crack another
issuer's active legacy code offline. Low because that holder can already mint
codes, and no legacy codes are created any more. Fix: return a derived
`inviteId` (first 16 hex of the hash) for `revoke`, keep the full hash
server-side, and expire remaining legacy rows in the same migration.

**L7 — `docs/SERVICE.md:37` still says "schema version 5".** The store is at
27 (`server/writer-fence.mjs:4`); `scripts/check-schema-version.mjs` gates
`README.md` and `docs/CURRENT-ROOM.md` only. Fix: rewrite the bullet to name
the current number from `STORE_SCHEMA_VERSION` and keep the version history
as history; add `docs/SERVICE.md` to the gate.

**L8 — Node and dependency drift.** `package.json` engines `>=24.19.0`;
`.github/workflows/hosted-denial-conformance.yml:23` pins Node 22 (its
`package.json` engines `>=20`; PR #142 proposes 24). `playwright` 1.62.1 is
pinned while 1.63.0 is published; `wrangler` 4.116.0 while 4.131.2 is
published; the root workflows use a floating `node-version: 24`. Fix: merge
#142; bump Playwright and wrangler in two separate PRs once CI is green on
each; consider pinning `node-version: 24.x` to the tested minor.

**L9 — Two webhook-import checks are missing on `main`.** A retried
`sync` with the same `requestId` but a different recording returns the
journaled receipt (`server/channel-import.mjs:125-129`), and a presented
webhook secret is only length-checked (`:68`). **Both fixed by #150**
(`sameRecording`, `validateWebhookSecret`). Fix: merge #150.

**L10 — The open-route inventory is hand-kept on `main`.**
`tests/invite-only-boundary.test.js` pins a literal list, and nothing checks
`docs/INVITE-ONLY-CHECKLIST.md` §1 or `docs/ROUTE-AUTH-TABLE.md` against it.
**Fixed by #152** (`scripts/open-routes.mjs --check` in `npm run check`,
inventory derived from `security: []` in `docs/openapi.yaml`). Fix: merge
#152 (see M6 for order).
