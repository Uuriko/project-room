# Busy canonical rooms: explicit current-write-proof qualification

This change removes the stale-checkpoint migration blocker for an explicitly selected current-state basis. It does not certify history, refresh the old content hash from current rows, or silently change the default.

`write-integrity.mjs` states its established authority: code-owned metadata and entity proofs track writes transactionally, detect unregistered changes, and do not defend against a database administrator replacing both data and proofs. `assertProjectionWrite` accepts the current metadata proof even when the historical baseline is older. The legacy proof-bootstrap comment explicitly distinguishes this case. The current v2 content digest includes room ID, sequence, exact metadata, all canonical message fields and optional canonical work fields; a digest for an older head cannot be compared with current bytes after legitimate writes. The persisted integrity row has no old metadata or old canonical row versions. Existing raw projection checkpoints and split replay snapshots do not supply that missing independent binding. Prospective capture-tail witnesses begin at capture and cannot retrospectively prove the older interval.

The operator first calls `planCanonicalReplayCapture(store,{roomId,expectedHead})` from `server/replay-canonical-plan.mjs`. The read-only plan returns the original checkpoint, current metadata hash, `checkpointComparison:'unavailable-stale'`, `historyProvenance:'unknown'`, `certified:false`, explicit proof limits and its hash. Execution must pass that exact hash and `contentBasis:'current-write-proofs'` to the existing `captureReplayWitness`. The plan binds the room, head, current metadata proof and original checkpoint; changed, absent, wrong or mismatched plans refuse. A fresh canonical checkpoint cannot use this optional path. A caller omitting the explicit basis still gets the original stale-checkpoint refusal.

Existing capture/codec/H-row readers and the canonical bounded state machine qualify the complete current set, count, retained archive membership and every existing row proof. The computed v2 current digest is recorded in the immutable qualification receipt as current evidence, explicitly not compared with the stale historical digest. Unregistered payload changes, missing row proofs, missing members, extra rows and unregistered metadata fail before publication. Fresh-head qualification still compares the anchored exact digest and retains its stronger forged-self-consistent-row negative controls.

The original checkpoint tuple is copied into the immutable capture receipt, so bounded staging cleanup cannot erase it. Through qualification the legacy integrity row is unchanged. At normalized publication the established publication code retires that mutable legacy row's old-format digest to NULL and records the new carrier metadata proof. That format transition remains explicit and returns unknown history/false certification; it does not rewrite an old hash as a successful historical check.
