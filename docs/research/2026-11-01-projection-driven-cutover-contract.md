# Projection-driven representation cutover contract

Proposal frozen after source 9730a6b37884641fb16ebb1f3c69c5edb366dd30. No runtime implementation or activation is claimed by this document. The existing projection capture/codec and recovery registration are the implementation base; no generic offline anchor tool will be added.

## Authority and result

The explicit operation converts an already protected current serving state at H into a bounded derived checkpoint. It neither replays, certifies nor writes pre-H journal bytes. Pre-H provenance remains unknown. Existing quarantine, history failures, invitation/grant/account authority and historical repair contracts remain unchanged. Strict full-journal replay remains separately anchored/refused. A completed representation receipt must say `basis: protected-current-state`, `historyProvenance: unknown`, and must not set the legacy parity certificate or report full semantic history verification.

Admission requires current valid metadata proof, existing valid entity/body/work proofs, protected counts/membership and exact provenance fields. Missing or invalid old proof refuses; the operation cannot manufacture a clean entity hash from content. Capture includes exact raw current projection bytes once (at most 4 MiB), H/head ID, existing independent hashes, representation identity and existing cursor identity in the same transaction. Only derived rows/phase receipts may be written. The existing legacy cursor and snapshot are not a source of authority and remain byte-identical throughout this representation-only slice.

Publishing a derived pointer alone does not remove the live JSON blob and does not optimize ordinary `store.room()` hydration or existing full-blob writes. This preparation boundary is distinct from active serving cutover. Required follow-on is wiring the existing explicit activation and reader/writer paths to the proved units, qualifying bounded dependency plans and preservation/rollback, and removing amplified whole-history hydration/writeback. Until that is done, it is not an active blob replacement.

Legacy archived feasibility is explicit: the protected archive count alone cannot prove every archived identity or field. Each archived row must already have its independent complete field proof, and a complete membership pass must satisfy the protected authority's exact retained/archive contract. Old backup rows with NULL proofs remain ineligible; neither current row content nor a newly computed count/root may manufacture those proofs. Current live feasibility is unclaimed until this admission is executed on an independently captured current input.

## Fixed H under concurrent writes

Inline bytes and their exact member/key order already have the immutable captured witness, completed-source root and receipt-bound leaf commitments. Entity references and archived messages require additional H-consistency: a later valid mutable row is not automatically its H value. Avoid copying the whole entity table. In the same optional sidecar, an explicit source-row domain records the exact old message/work fields and old independent proof on the first post-capture change. A post-H inserted ID records H-absence. Indexed current/shadow keyset pages merge bounded identities; no room-wide UNION sort is allowed. An untouched row may be fetched from its current table only while the active-generation dependency protocol proves it has not changed since H. Every row has SQL type/octet admission before payload fetch. Oversized or malformed capture makes the generation unusable; it must not weaken or block an ordinary serving write.

Body references continue to use the existing digest contract. Never retain a released/redacted body as a hidden sidecar authority. A missing body/work source, privacy erasure or source-representation replacement invalidates the generation and invokes derived cleanup through the existing lifecycle. Privacy qualification must demonstrate removal of inline witness bytes, shadow copies and leaves containing erased data; invalidation alone is insufficient. Ordinary physical backup retention remains its existing separate policy.

Message validation uses the approved `messageRowForWrite` projection and every MESSAGE_PROOF_FIELDS value, including sequence, channel/thread/reply/work/to/author, body, all timestamps, reactions, pin, record and reducer extras. Present valid row/proof bytes are preserved exactly; no upsert/reproof of equal authority. Retained inline members must have one exact matching independently proved row. Archived members come from already independently proved rows plus the protected archive count/retained set under the existing serving authority contract; incomplete membership or unknown extras refuses. Canonical/reference/inline authority and work/body representations are explicit admission variants, not defaults inferred from missing data.

## Post-H continuation and dependencies

Each consumed post-H event needs a prospective binding from the code-owned append transaction to its exact raw sequence/ID/body bytes and active generation. A fresh hash made by replay from an unproved current event is insufficient. The hook belongs at the existing event append boundary and uses the same sidecar/immutable phase receipt lifecycle. An older writer that produces no binding may continue serving, but the new consumer must remain pending/refuse at that event. No floor change is justified solely to hide such missing continuity.

Reducer execution uses the existing public reducer, never a fork. Only explicitly qualified dependency plans may advance. Every variable metadata/event/message/work/request/control value, aggregate fetch bytes, repeated proof reads, written rows and encoded receipts count toward the existing 256 KiB/200-row step admission; individual values remain at most 128 KiB. Missing/unknown dependency, unsupported event family, absent ancestry, lack of complete membership or exhaustion returns pending with no cursor advance. Actual runtime counters remain separate from logical reservations.

Reply-request entries stay partitioned. Ordinary descendant posts require proven ordered ancestor closure including terminal request barriers; request creation uses the protected count of ALL retained keys; answer/cancel use the exact addressed request and required message/member/work context. Unloaded entries never mean absent/public. Global retention/privacy/list selectors cannot consume a sparse reducer context. All metadata default effects of the existing reducer must be accounted for. The finite full-reducer versus bounded-context controls are acceptance requirements, not assumed from handler names.

## Independent equality and final quiet-head barrier

A bounded equality pass compares the completed candidate with current independently protected serving authority: exact metadata serialization/digest using shared existing codec, complete retained/archive membership, every message proof field, body/work digest and reference, and source/cursor representation identity. It can stream/continue candidate serialization; it cannot reparse or copy the growing live blob. A head change or dependency mutation records dirty identities and invalidates the affected equality work; unchanged leaves keep their completed comparisons. New dirty work must be fully drained before publication. A same-head mutation matters just as much as an event append.

`publishReplayRepresentation` will be the sole explicit final barrier. Inside one transaction it must verify: admitted schema and active generation; completed captured source/leaf bindings; candidate target T equals current room head and exact head ID; independent current metadata hash equals the completed candidate serialization digest; all protected dependency/membership counters still equal their last validated versions; dirty set empty; exact source representation and old cursor/snapshot identity unchanged; no missing prospective tail binding; all equality receipts belong to this generation and target. These are bounded indexed/scalar reads, with no final full scan. Any discrepancy rolls back pointer/receipt changes and leaves serving/cursors unchanged. Only then may it publish the new derived representation pointer and its explicit representation-only receipt. No current serving row/proof or journal write is part of this operation. Repeating an old request returns its historical original receipt; changed intent conflicts.

The first consumer is the existing explicit bounded operator lifecycle, not a new global default or background task system. Old readers/writers keep the existing serving representation. The new reader may consume the derived pointer only after the barrier and must refuse missing units; it cannot quietly fall back to strict historical replay. Unsupported tail events remain honest pending work rather than a complete cursor.

## Rollback, recovery and acceptance

Explicit abandonment first removes the active pointer and disables prospective capture, then cleans derived generations in bounded steps; no serving/history/quarantine or permission changes. Old-writer rollback requires abandonment and optional schema removal after an existing physical/whole-store backup. No older backup tool may silently ignore the table. Sidecar-only compatibility remains distinct from any future change to legacy serving/checkpoint format or schema floor.

Physical/whole-store backup and restore must preserve exact source witness, shadows, candidate units, receipts and representation pointer. Existing optional-table registration is the base. Reopen/restore performs exact schema admission; caches never cross connections. Checkpoint loss can rebuild only from retained authenticated capture/phase units and existing protected authority; total source/receipt loss refuses explicitly, without silently re-quarantining immutable historical events. Room-event export remains archival, not this restore artifact.

Required controls before activation: large captured state plus archive/entity all-field membership parity; corruption/missing proof and same-head source/dependency changes; continuous append and early/late edits during row capture/equality; bounded reply ancestry/terminal/count cases; old writer missing prospective binding; interruption/typed storage error/audit-write rollback at every commit boundary; immutable phase retry after later advances; post-capture witness/leaf/root/control/pointer tamper; zero journal writes and byte-identical serving proofs/cursors; privacy deletion/room deletion/import/restore/abandonment; actual Worker restart and honest physical counter/byte receipts. The preserved hidden pre-H journal mutation control remains a history-certification red and must not be relabeled fixed by representation equality.
