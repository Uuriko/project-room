# Bounded newest wake discovery

`GET /api/agent-wakes/poll?roomId=<selected>&order=newest` explicitly discovers a recent pending window. Authorization, host namespace, selected active membership, pause, work consent, rate limits and long-poll rechecks remain the existing poll contract. Missing order retains oldest-first behavior and its v1 cursors. Unknown/duplicate order or newest without a selected room returns 422. Newest requires the already installed, independently receipted bounded-delivery indexes; absent activation returns 503 rather than taking an unbounded legacy path.

An acquired selected-room listener heartbeat advertises `wakeSelection:{version:1,newest:true,roomId}` when those indexes are active. A newest poll echoes `order:'newest'` and the exact selected `roomId`; clients must validate both rather than assume an old server understood the selector. No new membership, listener, host permission or acknowledgement is granted.

Each source uses its existing selected-room partial index in descending `(created_at,signal_id)` order, with a strict less-than continuation. Existing admission remains 128 rows plus one scalar lookahead and 128 KiB admitted source bytes per journal; type/octet admission precedes payload transfer. These are source budgets, not total process heap ceilings. Combined pages retain the existing 50-signal cap and a common examined horizon across message and work journals. Fully filtered windows may return empty `pendingWakes` with `more:true` and an advancing opaque `nextCursor`. Newest cursor version 2 is bound to identity, room, host and direction; it is rejected by oldest pagination and vice versa.

This is recent discovery, never an assertion that historical source work is complete. Repeated fresh looks alone can starve a quiet older signal under continuous arrivals. Clients must retain and advance their independent oldest cursor, pace both reads under the existing poll budget, and keep formal/unknown work classification unchanged. Reads do not ACK signals, though existing poll activity and delivery-presentation accounting still writes. Subsequent work-policy room hydration is unchanged and outside the bounded journal scan claim.

Local qualification includes equal-timestamp reverse traversal, independent directions/scopes, filtered byte-window continuation, missing activation and oversized-field refusal, real HTTP selector/capability/auth/default checks, and actual Worker indexed scans at 1k/10k rows. Worker message scans read 129 scalar + 128 payload rows at both sizes; byte-limited work scans read 129 scalar + 15 payload rows at both sizes, with no temporary sort. No schema or DDL change is introduced.
