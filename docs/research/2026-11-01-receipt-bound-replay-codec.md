# Receipt-bound codec continuation

This production module remains explicitly unwired. It changes no serving rows, legacy cursor/snapshot bytes, grants or defaults. The optional table DDL remains off outside the synthetic fixture and conditional whole-store restore. Earlier red controls are preserved at 8acb5586f: existing code accepted a witness changed after the independent hash pass and refused a Muse-shaped replyRequests object; the proposed point-reader controls also exposed its then-missing API.

Each 16 KiB hash step now binds its exact chunk offset, length and SHA-256 into the existing immutable phase receipt. A tiny `source-chunk` row points to that receipt. Codec reads verify each fixed chunk against its receipt and the completed hash pass's independently captured metadata proof before parsing any span. A changed witness, a changed pointer and a reread of an earlier changed chunk during a spanning token refuse. No whole growing live projection is fetched or parsed.

Each emitted leaf is bound through at most 32 fixed-size commitments in its codec phase receipt. The domain-separated commitment frames header hash, generation, domain, key, source offset/length, payload length, exact payload SHA-256, and optional raw child-key offset/length/ordinal. A tiny `leaf-proof` row contains the receipt identity and index. `readReplayWitnessLeaf` admits bounded controls, checks the current captured source epoch/header, and verifies the exact leaf bytes against that independent receipt. Changing a leaf and recomputing its local self-hash, changing the pointer index, or changing source framing refuses. Local self-hashes are not authority. A point result remains uncertified.

`replyRequests` is partitioned into `metadata-entry` rows using an unambiguous JSON array of parent and decoded child key. Raw source key boundaries and order are retained. Duplicate nested/escaped-equivalent JSON keys refuse through the admitted SQLite tree check; repeated map keys also hit the indexed leaf identity check. The parent is a small framing record containing its exact source boundaries and total retained entry count. It is not a reconstructed whole object and does not permit treating unaddressed entries as absent. Unknown or unsupported reducer dependencies must refuse rather than fall back to an empty map. Modern commands are unchanged.

The codec's supported source ceiling remains 4 MiB; each value is at most 128 KiB. A scanner input ends at the current fixed chunk boundary. Each transaction reserves 64 KiB for bounded controls/input and charges every distinct fetched chunk, its at-most-4-KiB receipt and at-most-512-byte pointer before fetching. Repeated chunk fetches share only a transaction-local cache; spanning tokens can touch at most nine fixed chunks. The complete charged input must fit 256 KiB. Output bytes, leaf/proof rows and the encoded at-most-4-KiB receipt are separately admitted. These are payload admission bounds, not a claim of a 256 KiB heap peak or CPU bound: decoded objects, transient buffers, SQLite JSON work and the fixed witness's native slicing can cost more. No growing token buffer or prefix rewrite is retained across steps.

The original October 31 private Muse backup shape now passes the pure codec with unchanged caps: 2,376,017 bytes; 6,779 retained messages; 305 reply-request entries; 232 scanner steps; maximum value 40,255 bytes; maximum scanner state 733 bytes. All 7,094 admitted value spans passed the existing nested duplicate-key predicate. This is an offline shape check, not evidence of current live eligibility or adoption of missing independent archive proofs. The old refusal is retained in the private 0700/0600 shape journal. No production data was copied into source or logs.

The shared normal serializer extraction is unchanged from 7c26ab4ca. Bounded semantic replay, complete addressed dependency selection, independently proved archive content/membership, historical receipt recovery after checkpoint loss, explicit derived-unit abandonment for rollback, and bounded final publication remain activation gates. Partition completion never means serving certification.

## Completed-source inclusion cure

Source 5fb8 was not trust-qualified. Red commit 22b05796a demonstrates restoring an older valid completed hash checkpoint after creating a newer partial fork receipt for changed bytes. A pointer to that partial receipt did not establish membership in the completed pass.

The cure adds a fixed depth-eight source tree (at most 256 chunks, 4 MiB) in the same typed table. Chunk framing includes header/generation, index, exact offset/length, total captured bytes and exact bytes hash. Every hash receipt binds its SHA continuation and tree root atomically; the completed receipt exists only after the independent full metadata digest matches. A codec chunk must prove inclusion in that completed root. Tree nodes and local self-hashes are not authority. Each hash update reads eight sibling and eight existing-path positions and writes eight bounded nodes; codec inclusion reads eight siblings per distinct chunk. Their bytes are charged before reads. The scanner dynamically reduces the record count for a spanning token to retain the logical persisted-unit reservation of at most 200. `logicalUnitRows` is not a claim about Cloudflare's physical storage rows-read/written metrics.

A paired actual Worker probe replaced only replay-cutover.mjs with verbatim 5fb8 source under the same current fixture/shared codec. Before schema-cache optimization, prior hash steps used 24 statements / 6,331 storage rows read / 5 written. The membership candidate used 48 statements / 6,347 read / 21 written on chunk one, and 6,376 read / 14 written on chunk two. Most baseline reads came from eight repeated sqlite_master scans. These receipts preserve the measured inefficiency rather than claiming a physical 200-row ceiling. The next explicit schema-admission cache must retain DROP/recreate, unrelated-DDL, reopen and rollback detection.
