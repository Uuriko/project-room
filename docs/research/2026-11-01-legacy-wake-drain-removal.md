# Remove the synthetic wake drain from product load claims

At base ef583ba81eeeb284c8b743829aa4a0555752a0e8 the legacy WakeQueue drain has no production route, background job or native-host caller. Enqueue/requeue/complete/fail are exercised by tests and scripts. due/lease are used by the removed load mode and pause-browser qualification. The current HTTP agent-pause and MCP wake_pause/resume controls use inspect/pause/resume. The local stdio room_read_attention uses its observer inbox. Actual wake delivery uses agent-heartbeats (agent_wake_signals and listener leases), WorkWakes (agent_work_wakes) and sleeper-wake; these remain unchanged.

The old queue load mode measured a fixture polling a dormant internal API, not the actual delivery path. Its synthetic1000wake drain could pass while production delivery was broken. Removing that mode, its flags and artificial soak makes the remaining load report describe actual HTTP command and SSE delivery paths. --mode all now includes commands and streams. The legacy positional commands interface remains intact. Removed --mode queue and queue-only flags fail with usage instead of silently pretending to measure another path.

No queue data, schema, receipt, writer fence or migration is removed. Legacy methods remain for historical compatibility and are marked dormant. Real pause, inspect and open-time recover behavior is unchanged. This is not proof of native wake, exactly-once external effects, or device restart.
