Before, the screen called itself “Connect your existing agent” but made invitation redemption primary, although redemption creates a new seat. The existing-account link was presented as optional. After, the account reconnect path is primary, and invitation joining is an explicit new-seat alternative. Explicit connection=invite opens the invitation form directly and still needs no Room signup. The confirmation screen labels the new seat accurately; cancellation remains visible and retains the existing nonce/CSRF and registered callback behavior.

For a default request with a valid signed-in account and an already eligible seat, the existing account consent screen opens directly. A single eligible option is already selected by the existing select; Allow is always explicit. Explicit invite never switches principal type. No new membership, sponsorship, grant authority, identity rotation or token protocol is introduced. Account-link URL construction preserves the original PKCE challenge/method, state, resource, scopes, client, registered callback and remaining query fields, changing only connection=account.

Normalized agent discovery previously called retired whole-room hydration unless the client had an exact preferred room/member hint, so generic ChatGPT clients saw no normalized agents. That branch now reads existing protected room metadata and the existing bounded authority census. Managed-connection/adoption/configured-seat control proofs are unchanged: being a sponsor alone still does not prove account control. Existing membership census limits are retained; this is not an unbounded roster API.

78 focused Node tests pass, including actual HTTP exact-seat consent/code/PKCE exchange, unrelated/expired account refusal, no automatic grant, original invitation lost-response exact retry/cancel/revocation controls, adoption rejoin refusal, and original interrupted refresh/token-save rollback controls. Account consent can be reloaded/reissued after an interrupted browser flow without creating or replacing any seat; authorization codes retain their original semantics and are not claimed identical across repeated Allow posts.

Actual before and after HTTP-rendered browser screens were checked at 1280 and 390 pixels, with screenshots. The local browser test forwards production HTTP through an isolated browser-origin proxy, keyboard-focuses the primary link, checks preserved query values, supplies the synthetic signed-in cookie, selects the existing managed seat and submits explicit Allow. It captures the real server's 302 at the proxy boundary; the synthetic external host callback is not a live-host qualification. Actual callback target/state and code exchange are separately exercised over real HTTP in Node. Login redirect return preservation is tested over HTTP; the browser fixture stops the login handoff rather than loading/draining the full application's long-lived streams.

No production calls, account transfers, real identities, merges or deployments. Existing accountless invited grants cannot be silently converted into account-controlled seats: expired/revoked accountless grants still require the established invitation or explicitly approved adoption path. This patch does not promise unattended external-host setup or change refresh lifetimes.
