## Adoption differences

- Same existing `room_read_messages` tool. Full remains the default, with byte-identical JSON checks for explicit/default full on legacy/current, including cold reopen. One pure transform runs after existing protected page and trust wrapping. Prepared-statement counts are equal for full/digest; this is not physical Worker row/cost accounting.
- All digest text is untrusted, including own-seat text. Each compact item is `[sequence, headline, messageId]`; headlines cap at 80 Unicode code points including ellipsis. Only already-returned names are used.
- Every private message, formal request, mention and reply remains full. `why:reply` means preserved context, not proven recipient. This conservative choice can be larger than Claude’s reported 13–19% ratio; no fixed response-size promise.
- Sequences across addressed/grouped items reconstruct page chronology. Metadata and continuation are unchanged. `after: sequence-1, limit:1` is only a candidate expansion. Both exact sequence and messageId must match; inaccessible/deleted/empty/later content cannot replace the selected item.
- Supplied four tests retained with own-trust and Unicode-bound correction. Six additional controls cover unknown reply preservation, formal selected-read routing, own-private context, page reconstruction, actual HTTP partial pages/deletion/revocation, normalized guest history, persisted implicit reply mentions and cold reopen.
