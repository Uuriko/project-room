### Behavioral notes

- STALE `scripts/scan-secrets.mjs:4` — `"Exit 0: no secrets found. Exit 1: at least one finding (blocks the PR)"` contradicts `scripts/scan-secrets.mjs:61` (`process.exit(2)` when `git diff <base>...HEAD` fails — the environment-error path exists but is undocumented in the header).
- STALE `docs/SECRET-SCAN.md:11-13` — `"Same detector, same line allowlist, same scope policy — the two gates never disagree about a line"` contradicts `scripts/secret-scan-diff.mjs:159-179` (`scanAddedUnits` applies the `.github/secret-scan-allowlist.txt` path allowlist) vs `scripts/secret-scan-check.mjs:178-205` (`runTreeScan` never consults any path allowlist). A path-allowlisted file passes the diff gate but still fails the tree scan in `check.mjs`.
- BUG? `scripts/disk-door.mjs:76-89` — a crash between the per-entry `saveState` in the relay loop and the final `saveState` (after `appendFileSync`) replays `roomMessages` from the stale `state.seq` on the next run, appending duplicate room→channel lines to the channel file — room→channel writes are not deduped the way channel→room writes are (the latter skip `room:`-prefixed lines at `scripts/disk-door.mjs:34`).
- `scripts/scan-secrets.mjs:21,61-72` — the `secrets-allowlist` escape hatch is a free-text marker: any added line containing it (case-insensitive) is skipped entirely, including by future pattern additions. The `git diff` on failure path exits 2, i.e. fail-closed.
- `scripts/secret-scan-check.mjs:19-20` — the tree scan skips itself (`SKIP_FILES` includes `secret-scan-check.mjs`), so its own `ALLOWLIST` entries containing secret-shaped strings (e.g. the web-push test vectors, the agent-card public key) are never self-scanned. The diff gate imports the same `SKIP_FILES`, so it skips it too — but `scan-secrets.mjs` (zero-bug gate) has no path filter and would still catch provider-prefixed patterns added there.
- `scripts/secret-scan-diff.mjs:195-197` — `run()` checks `if (!base && !staged && !files)` after defaulting `base = "origin/main"`, so this guard only fires when `--base` is given with no value (arg parser consumes `argv[++i]` → `undefined`) → exit 2. Fail-closed, but the error message ("--base requires a value") is reached via an indirect path.
- `scripts/access-review.mjs:44-49` — `ownerKey()` validates the *name* of the env var (`^[A-Z][A-Z0-9_]*$`) before reading it, and the *value* as 43 base64url chars; `--revoke-identity` is refused with `--origin` (`scripts/access-review.mjs:31`) so revokes can never be issued over HTTP — store-file only.
- `scripts/audit-invitations.mjs:23-26` — the catch swallows the original error entirely and prints a fixed fail-closed message with exit 1; deliberate (no detail leakage), but operators get no diagnostic beyond "schema-v8 required / reconcile from backup".
- `scripts/dependency-audit.mjs:63-108` — `parseAuditJson` explicitly detects npm's error-JSON shapes (registry 403 `{message, method, uri, statusCode}`) and raises `AuditError` → exit 2, so a failed audit can't be misread as clean. Default `--fail-on=high` means low/moderate vulns print in the report but don't fail.
- `scripts/github-door.mjs:65-75` — `readCursor` only trusts `github-actions[bot]` comments for the outbound cursor, and the marker regex is anchored to the start of the body; participant comments can't forge the cursor. `runInbound` (`scripts/github-door.mjs:121-130`) requires `action === "created"` and the exact door issue number.
- `scripts/github-door.mjs:36-48` — `parseDoorComment` strips a leading `/room` command and honors `/skip|/nope|/no-room` opt-outs; bots are rejected unless their login is in `ROOM_DOOR_ALLOW`. `inboundCommand` labels every relayed message "via GitHub (unverified)" (`scripts/github-door.mjs:52`).
- `scripts/github-work-sync.mjs:13-24` — `parseRoomWork` caps at 10 refs per PR body and dedupes; `TERMINAL` states (`completed`, `superseded`) are skipped at `scripts/github-work-sync.mjs:46`. The sync message itself is posted *on the work item* (`workItemId` in the command data).
- `scripts/fuzz-mime.mjs:245-270` — numeric CLI args are validated (NaN/negative/out-of-range → exit 2 with the flag name), explicitly to avoid a false-green where `--iterations=abc` becomes NaN and the loop runs zero cases. Boolean flags accept only `--flag` / `--flag=<bool>`; `--skip-corpus false` (space form) sets true and then errors on the stray `false`.
- `scripts/fuzz-mime.mjs:64-75` — `checkOne` classifies outcomes as `ok` / `error` (MimeError) / `slow` (> maxMs) / `unclean` (any other throw); only `ok`/`error` pass. `maxMsSeen` tracks the slowest case in stats.
- `scripts/reachability.mjs:119-135` — `specifiers()` strips comments with a string-aware scanner (regex literals containing `//` inside strings survive; actual `//` comments are dropped), then matches four import forms. `pathTokens()` separately harvests `*.mjs|js|cjs` tokens from `package.json` scripts and workflow `node <file>` mentions (`scripts/reachability.mjs:137-139`).
- `scripts/reachability.mjs:36-40` — KEEP entries carry dated/owned reasons (e.g. PR #1615 mount lease expired 2026-10-07T00:23Z); verified against the worktree that `server/http.mjs` still has no merge-queue mount, so the entry is still accurate — not stale, just time-bound.
