### Behavioral notes

- Destructive actions require an explicit `{"confirm": true}` body: key rotate/revoke (agent-plugin-routes.mjs:268–283), identity-secret rotate/revoke (agent-plugin-routes.mjs:659–693). An empty POST returns the required shape instead of mutating — a probe can never retire a live credential.
- Key actions and identity-secret rotate/revoke are wrapped in `store.transaction` with auth re-checked under the writer fence (agent-plugin-routes.mjs:278–286, 778–808).
- `GET /api/agent-keys/{keyId}/...` is not matched by KEY_ACTION_ROUTE (POST-only dispatch, agent-plugin-routes.mjs:929) and falls through; a malformed keyId never reaches the store.
- Webhook secret policy: the signing secret is never returned at all (RC-2026-09-27-2729); the 201 carries a `secretRef` sentinel and verification is server-side via verify-delivery (agent-plugin-routes.mjs:486–496, 520–544).
- Directory visibility tiers: public cards (no credential) < room-visibility cards (valid room-member credential) — private cards stay invisible on both views; invalid credentials are 401, but valid credentials without membership silently fall back to the public view (agent-plugin-routes.mjs:126–148).
- Room access tokens satisfy heartbeat auth but are strictly pull-only: `assertRoomKeyPullOnly` refuses wakeUrl/pushNotification, and room keys get a namespaced hostId via `roomKeyHostId` (agent-plugin-routes.mjs:778–808).
- STALE docs/openapi.yaml:9875–9888 — the `/api/agent-keys/{keyId}/{action}` entry documents only 200/401/404/429 and no request body, but the code requires `{"confirm":true}` and returns 422 `confirm_required` otherwise (server/agent-plugin-routes.mjs:276–280).
- STALE docs/openapi.yaml:14313–14338 — the `/api/agent-identities/{identityId}/rotate` entry documents no `{"confirm":true}` body or 422 `confirm_required`, contradicting server/agent-plugin-routes.mjs:664–668.
- STALE docs/openapi.yaml:14339–14362 — the `/api/agent-identities/{identityId}/revoke` entry has the same gap vs server/agent-plugin-routes.mjs:685–689.
- BUG? server/agent-plugin-routes.mjs:615 — `unverifyIdentity` issues no `rate()` call, unlike every other mutating route in the file (issueKey:207, keyAction:269, verifyIdentity:606, rotateIdentitySecret:660, revokeIdentitySecret:681) — a destructive owner action with no rate limit.

### Behavioral notes

- The `/sweep` and `/metrics` literal envelope paths are resolved BEFORE the `{id}/transition` regex in http.mjs (server/http.mjs:3709–3713) so they never read as an envelope id.
- Strict body shapes everywhere: every required key present, NO unknown keys — the local `shape()` helper (inbox-collab-routes.mjs:51–56) mirrors the rooms block's `exact()` idea.
- HEAD requests reach `handleInboxCollabCore` (inbox-collab-routes.mjs:77) but every read case checks `req.method === "GET"`, so HEAD yields 405 `method_not_allowed` — HEAD is not a usable read alias on these routes.
- Typed-envelope idempotency: `requestId` on POST /envelopes dedupes (200 + receipt.duplicate); handoffs dedupe on an already-open handoff for the thread (inbox-collab-routes.mjs:343–361, 294–326).
- Routing-policy M-7(a) trust rule: only the room owner or the agent itself may set that agent's policy — callers cannot attribute policy to other agents (inbox-collab-routes.mjs:279–293).
- Envelope party rules are enforced at the store layer: only the recipient may accept/reject/complete, only the sender may cancel, either party may escalate (docs/openapi.yaml:12056–12090, STATUS_BY_CODE in inbox-collab-routes.mjs:18–45).
- STALE docs/openapi.yaml:11918–11920 — the `/api/rooms/{roomId}/collab/routing/policy` entry lists responses 401/200/422 only, but the code returns 403 `routing_forbidden` when the caller is neither the room owner nor the named agent (server/inbox-collab-routes.mjs:288).
