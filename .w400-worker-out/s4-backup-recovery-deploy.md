### Behavioral notes

- Fail-closed backup core: `backupRoom()` (`server/backup.mjs:36-63`) creates a fresh `room-backup-*` subdir (mode 0700) per run, never reuses or overwrites; opens the source DB read-only; copies via the sqlite online-backup API; then opens the COPY and throws unless attachment bytes hash to their stored sha256 (`server/backup.mjs:57`), `auditRecovery` and the invitation audit pass, and the watermark sidecar is written (0600). The wrapper's "Live data was not replaced" claim (`backup-room.mjs:12`) is structurally true — no code path writes to the source.
- `backup-verify.mjs` exit contract: 0 = ok or not-due skip (`ok:true, ran:false`), 1 = cycle ran and failed, 2 = usage error (usage text at `backup-verify.mjs:260-271`). `runBackupCycle` requires BOTH `result.verified === true` and `verification.ok` before `ok:true` (`backup-verify.mjs:235`).
- Legacy-watermark tolerance is explicit: watermarks without `digests` still verify, and the check detail says "legacy watermark: counts only, byte equality not provable" (`backup-verify.mjs:145-149`) — consistent with docs/BACKUPS.md:88-93.
- `--print-cron` quotes every operator-controlled value with `shQuote()` so a path containing `"`, `$`, backticks, or whitespace cannot inject into the crontab (`backup-verify.mjs:33-36, 288-293`); state file is chmod 0600 (`backup-verify.mjs:219`).
- `restore-room-backup.mjs` refuses to restore over an existing file (`:72`), and on replay failure removes the partial destination including `-wal`/`-shm` before re-throwing (`:80-84`); `--save` uses flag `wx` so it will not clobber an existing reassembled file (`:78`). With `--audit strict` (default) a recovery-audit drift aborts the restore; `--audit report` proceeds and reports it.
- `deploy-recovery.mjs` `snapshot` refuses to proceed unless `git rev-parse HEAD` equals `$SHA` (`:87-88`), the candidate schema parses from the exact blob (`:89-90`), and an exact previous 100%-traffic version id is known for both workers (`:96-97`). `recover` only rolls back workers where the observed allocation changed from the snapshot (`:53`); post-rollback it re-reads allocation AND `/api/version` and demands `servedBy === 'worker'`, `status === 'ok'`, and matching sourceRevision, else `rollback_unverified` (`:58-59`).
- `rollback-readback.mjs` demands the expected version UUID hold exactly 100% of traffic exclusively — any other version with nonzero percentage fails it (`rollback-readback.mjs:22-28`); door URLs are rejected if they carry credentials, query, or fragment (`:29-33`).
- `release-checkpoint.mjs` exit-0 semantics are a trap for the unwary: 0 means "collection complete", explicitly not "ready to merge/deploy" (`release-checkpoint.mjs:213`); only `--output DIRECTORY` creates files, everything else is stdout.
- `release-evidence.mjs` honest-labeling rules (`:19-43`): `skipped > 0 || todo > 0` → `passed-with-skips` (never `passed`); any porcelain output → `dirty`; `live` requires every probe to be 200 with equal expected/actual sha256, otherwise `mismatch`/`unverified`. Without probes, exit 0 needs only suite=`passed` + candidate=`clean`.
- `cold-start-probe.mjs` pass is strict: `status === 200 && revision && elapsedMs < maxMs && !error` (`:44`); note elapsed must be strictly under budget, not equal.
- `smoke-prod.mjs` probe C deliberately asserts the 401-adjacent refusal rather than the honest 402, because a true 402 would need an authenticated grant-less identity and provisioning one would write to production (`smoke-prod.mjs:25-34`).
- `backup-drill.mjs` and `restore-rehearsal.mjs` create their temp dirs with `mkdtempSync(join(tmpdir(), …))` (respects `TMPDIR`) but only clean up on the success path (`backup-drill.mjs:68-69`); an assertion failure leaves the synthetic-room temp dirs behind until the OS reaps them.
- `watch-deploy-drift.mjs` treats "unknown" prod revisions (not a 40-hex SHA, or no such commit locally) as `reason: "unknown"` with `known:false` (`:48-49`) — which the workflow surfaces rather than silently passing.
