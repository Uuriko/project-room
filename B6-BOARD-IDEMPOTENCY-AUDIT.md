## Verdict convention (for the B1 matrix)

- **yes** — a keyless retry of the same payload converges safely: a no-op, a stored-response replay, or a refusal that correctly names the state. No double-write of anything, no destructive side effect.
- **partial** — keyless retry degrades safely in the common case but has a known gap: double-writes metadata (history entries / wakes / events), refuses where a replay would be correct, or relies on client-supplied preconditions.
- **no** — keyless retry double-executes with a harmful effect, or makes a safe retry impossible.

B2 scored safe-refusal ops (create/claim/close → 409/422) as PARTIAL ("errors instead of returning the prior result"); this report scores them **yes** per the B4 convention (the refusal *is* the safe outcome). The per-op notes record where this changes B2's letter.

## The mechanism situation (there is no single one)

Unlike the bounty surface (B4's `BountyEscrow.idemExecute`), the board has **no unified idempotency mechanism**:

- **No key surface.** `grep -i "idempot|requestId|request_id|Idempotency-Key"` over `server/work-claim-routes.mjs`, `server/work-claims.mjs`, `server/claim-coordination.mjs` → **zero hits**. Every board route body goes through `shape()` (`server/work-claim-routes.mjs:109-114`), which 422s unknown keys — a client cannot even smuggle a `requestId` in. Land-queue routes are the same: `exact(data, ["repo","prNumber",…])` (`server/http.mjs:3277`), `exact(data, ["itemId"])` (`:3285`), tip keys `["itemId","sourceRevision","buildId"]` (`:3288`) — extras 422.
- **Safety is state-guard-shaped.** create → 409 `work_claim_exists` (route `has()` check, `:910`); claim → 409 `work_claim_conflict` (route pre-check `:973-976` + `claimWork`'s `state === "unclaimed"` guard); close/cancel → 409 `work_claim_terminal` (`work-claims.mjs` `nextClaimState` → null, `closeWork`); state-transition retries → 422 via the `CLAIM_LIFECYCLE` table (`work-claims.mjs:42-52`, `TRANSITIONS` `:64`).
- **Round CAS exists in exactly two board ops.** PR-link: `expectedClaimedAt` + `expectedHistoryLength` are **mandatory** (`work-claims.mjs:638-650`, stale → 409 `work_claim_conflict`; same-round duplicate → `return work`, byte-identical no-op, `:676`). Release: now also **mandatory** — `releaseWork` (`work-claims.mjs:770-789`, E5/D4, QA-200 2026-10-08) requires both preconditions; the route requires them in `shape()` (`work-claim-routes.mjs:1205`) and maps a stale round to 409 (`:1218-1229`). This closed B2's #1 worst gap (release destroying a newer claim round). Update: the same preconditions are **opt-in** only (`work-claim-routes.mjs:1059-1072`); absent, the legacy path stays round-blind and the code says so verbatim.
- **Races serialize on `BEGIN IMMEDIATE`.** All board routes run inside `registry.transaction(run)` (`work-claim-routes.mjs:633-636`), which is `store.transaction` → `BEGIN IMMEDIATE` (`server/store.mjs:671`), against `PRIMARY KEY (room_id, claim_id)` (`server/work-claim-sqlite.mjs:48`). Check-then-act (e.g. create's `has()` + insert) is race-safe in the single-process server. Land-queue rows carry `UNIQUE (room_id, repo, pr_number)` (`server/land-queue.mjs:71`).
- **The MCP stdio path is a different world.** `store.command` journals commands with `(room_id, actor_id, command.id)` uniqueness and fingerprint-mismatch → 409 `idempotency_conflict` (`server/store.mjs:4593-4597`) — a real idempotent command journal. Board REST ops do **not** ride it; only work-tool commands (`acquire_claim`/`release_claim`/`renew_claim` via `recorded()`, `server/mcp-full-profile.mjs:126-137`) do. The board's own MCP tools are narrow: `room_link_work_claim_pr` and `room_close_work_claim` only (`server/mcp-full-profile.mjs:244-276`); land-queue MCP tools (`add_land_item`, `remove_land_item`, `report_tip`) exist in `server/mcp-room-profile.mjs:421-438` but pass **no** requestId on main.
- **Events commit with the row.** Every committed board change appends one `work_claim.updated` room event inside the same transaction (`work-claim-routes.mjs` `commit()` helper; `server/work-claim-events.mjs`). A retry that re-executes therefore double-emits (release/reassign paths), which is why re-stamp findings below count as side effects, not just history growth.

## Cross-cutting findings

1. **No requestId journal anywhere on these surfaces.** Board: zero hits for `idempot|requestId|request_id|Idempotency-Key` in the board modules. Land queue: zero on main. The `IdempotencyCache` (15-min TTL, returns original response on key hit) lives at `bridge/lib/idempotency.mjs` but is wired only into `bridge/lib/bridge.mjs` — no board or land-queue transport uses it. Note the asymmetry with adjacent surfaces that DO have keys: project-offers (`requestId`, `docs/openapi.yaml:980-987` — "Exact same requestId/body replay returns original result; changed input returns 409"), bounty-escrow (`Idempotency-Key`/`idempotencyKey`, B4), and the MCP `store.command` journal (fingerprint-mismatch → 409 `idempotency_conflict`, `server/store.mjs:4593-4597`). The board and land queue are the odd ones out.
2. **Doc/route drift: four board ops are documented but REST-unroutable.** `docs/openapi.yaml` documents `POST /api/rooms/{roomId}/work-claims/{claimId}/close` (`:5674`), `/cancel` (`:5713`), `/provenance` (`:5475`), and `/premise-invalid` (`:5518`) — but `server/http.mjs` has **no regex** for any of them (the work-claim route table is `:3459-3475`, and `grep '"close"\|"cancel"\|"premise-invalid"\|"provenance"' server/http.mjs` hits nothing). POSTing those paths falls through to 404 `not_found`. The handler branches exist (`work-claim-routes.mjs:1183`, `:1340`, `:1355`) but are REST-unreachable. Close/cancel survive via MCP (`room_close_work_claim` → `closeWorkClaim`, `server/mcp-full-profile.mjs:263`); **premise-invalid and provenance have no MCP tool at all** — they are reachable from nowhere on main. Idempotency consequence: the premise-flag op (`partial` — re-stamps on retry) currently has no live caller; if/when it is routed, its retry behavior lands untested.
3. **Delta since B2: release is fixed, reassign/renew/update-legacy are not.** B2's worst gap (release destroying a newer claim round, E5/D4) is closed on main: `releaseWork` (`server/work-claims.mjs:770-789`) requires `expectedClaimedAt` + `expectedHistoryLength`, the route requires them in `shape()` (`server/work-claim-routes.mjs:1205`), stale rounds → 409 (`:1226-1229`). B2's #2 (reassign, no CAS) and #3 (renew, re-extends) and #4 (update legacy path clobbers) are unchanged.
4. **Concurrent `add_land_item` 500s.** `#addExecute` runs `#byPr` **outside** the write txn (`server/land-queue.mjs:600`) and inserts inside it (`:607-624`); the `UNIQUE(room_id, repo, pr_number)` constraint (`:71`) is the only backstop, and its violation surfaces as a raw 500, not a graceful dedupe. Two agents landing the same PR concurrently get one 201 and one 500 — a retry-safety cliff for exactly the client (a land bot) most likely to double-submit.
5. **A requestId mechanism for land-queue already exists off-main (verified, not merged).** Commit `e5e9e6e22` on branch `jill/product200-b6-land-queue-requestid` (prior B6 attempt) adds `land_queue_idempotency` (`PRIMARY KEY (room_id, request_id)`) and a `#requestKey` gate: same key+op+actor+input-hash → replay stored 2xx byte-identical; different → 409 `idempotency_conflict`; in-flight → 409; failures delete the placeholder so retries re-execute fresh (never replays a stale 503 `github_unconfigured`); bad shape → 422. REST (`server/http.mjs`) and both MCP tools (`server/mcp-room-profile.mjs`, `server/mcp-hosted-tools.mjs`) plus `docs/openapi.yaml` are wired. I re-read the mechanism against the code on that branch: the gate is sound (INSERT OR IGNORE claim + PK, `BEGIN IMMEDIATE` underneath). With it, all three land-queue ops become **yes** (key required to benefit; keyless behavior unchanged). It is NOT on origin/main — B11 should adopt it as the base or supersede it, not re-derive it. Fail-first tests ship with it (`tests/land-queue-idempotency.test.js`, 8 tests).
6. **The `IdempotencyCache` in `bridge/` remains the ready-made board primitive.** B2 flagged it; still unused by board/land-queue transports. Wiring it (or a durable variant, since bridge's is 15-min in-memory) into the board routes would convert every `partial` above toward `yes` — but the round-CAS pattern (`releaseWork`, `appendWorkPullRequest`) already covers the destructive cases without a journal; the remaining `partial`s are metadata double-writes (notes, reassign history, renew lease bumps), where a journal buys exactness, not safety.

## Worst finding (for B11)

**`reassign` has no round binding — a retried reassign re-fires attention wakes and room events** (`server/work-claim-routes.mjs:1234-1257`, `server/work-claims.mjs:887-902`). Repro: owner POSTs `/reassign {newOwner, expectedNothing}` (there is no precondition field to send), the response is lost, the client retries → the second execution re-stamps `reassigned:<target>` history, re-clears the target's attestations/reviews, and re-emits the `attention: "assigned"` wake + `reassigned` room event to the target. Unlike release (fixed by `releaseWork`) and PR-link (mandatory CAS), reassign accepts no `expectedClaimedAt`/`expectedHistoryLength`, so a stale retry acts on whatever the row is. The fix is the `releaseWork` pattern applied to `reassignWork` (require the round preconditions in `shape()` at `:1235`, compare in the pure function, 409 on mismatch) — the same shape as #2088 did for release. Second: `renew` — an uncited retry silently extends the lease again with no refusal possible (`server/work-claims.mjs:607-633`); a renew-token bound to the current lease window (or the same round CAS) would close it.

## Verdict summary for the B1 matrix

- **yes:** create, claim, update (state moves + PR-link), release (fixed since B2 via `releaseWork`), close/cancel, review attestation, premise-clear, config, sweep. Land-queue ops only with the off-main requestId mechanism (finding 5).
- **partial:** update (note-only double-stamp), update legacy stale-clobber path (opt-in CAS defaults off), review verdict (identical → no-op; delayed-after-newer clobbers — code's own comment), reassign (re-stamps + re-fires wakes), renew (uncited retry re-extends), premise-flag (re-stamps; currently unroutable). Land-queue on main: add (concurrent 500), report_tip (converges, no replay).
- **no:** `remove_land_item` on main — retry after success → 404 `land_item_not_found`; a safe retry is impossible without a key (key rejected by `exact()`). The single non-idempotent delete in the slice; the off-main mechanism closes it.
